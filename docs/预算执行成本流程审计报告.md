# 预算→执行→成本全流程审计报告

> 审计范围：预算编制→审批→基线确认 / 执行阶段(任务/计划/门禁) / 成本归集(采购/外包/费用/工时) / 日报周报 / 事项管理 / 变更管理
> 审计方法：逐函数追踪所有分支、校验、异常处理

## 一、预算编制与审批流程

### 1.1 `saveBudgetDraft` — 预算草稿保存

| 检查项 | 结果 | 说明 |
|--------|:----:|------|
| PM 角色校验 | ✅ | `actor.role !== 'project-manager' \|\| actor.id !== p.pmId` |
| 建设期可写 | ✅ | `assertConstructionWritable` |
| 无待审批/待确认预算 | ✅ | 检查 `approvals` 中同项目待审批或待确认基线 |
| 草稿版本冲突 | ✅ | `revision` 匹配检查 |
| 科目/金额校验 | ✅ | `validateBudgetDraft` 含科目匹配、金额非负 |
| 费率快照 | ✅ | `snapshotBudgetRate` 记录当前费率版本 |
| **问题** | ⚠️ | `snapshotBudgetRate` 中 `selectCostRate` 可能 throw（无匹配费率时），但调用方未捕获，错误会冒泡到 UI |

### 1.2 `submit-budget-draft` — 预算草稿提交

| 检查项 | 结果 | 说明 |
|--------|:----:|------|
| 提交校验 | ✅ | `validateBudgetDraft(state, draft, true)` — 含超概算原因/措施/责任必填 |
| 递归调用 `transition` | ⚠️ | 调用 `transition(state, {type:'submit-budget',...})` 导致 state 被 `structuredClone` 两次。非 bug 但浪费内存 |

### 1.3 `submit-budget` — 预算提交（business-domain.ts）

| 检查项 | 结果 | 说明 |
|--------|:----:|------|
| 角色校验 | ✅ | PM 或 finance，PM 须是项目主 PM |
| 建设期可写 | ✅ | `assertConstructionWritable` |
| 预算数据校验 | ✅ | 金额非负、科目合计匹配、无负值 |
| 无重复审批 | ✅ | 同项目无待审批或待确认预算 |
| 概算必填 | ✅ | `projectEstimate` 必须存在 |
| 超概算分支 | ✅ | `budgetOverruns` → 超概算须 executive 审批，否则 pmo 审批 |
| 基线快照 | ✅ | `budgetBaselineProposal` + `planningSnapshot` |
| 决策事项创建 | ✅ | 自动创建 `decision` 记录 |
| **问题** | ⚠️ | `budgetOverruns` 只检查总成本和三大科目（SUB-01/02/03），不检查 SUB-04（期间费用）和 SUB-05（准备金）的超概算。SUB-05 准备金本身是概算的一部分，但超概算检查遗漏了 SUB-04 子科目 |

| 检查项 | 结果 | 说明 |
|--------|:----:|------|

| 检查项 | 结果 | 说明 |
|--------|:----:|------|
| PM 角色校验 | ✅ | |
| 建设期可写 | ✅ | |
| 仅执行中项目 | ✅ | |
| 说明必填 | ✅ | |

| 阶段切换 | ✅ | `执行→收尾/客户终验` |
| 释放比例更新 | ✅ | |
| **问题** | 🔴 | `stage-gate` 可作为独立 action 直接调用，绕过 `review-plan` 的基线校验和审批快照。虽然角色限制为 PMO，但 PMO 可以直接调用 `stage-gate` 跳过完整的计划变更流程 |

## 七、总结

### 🔴 严重问题（1 个）

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 1 | **`review-plan` 阶段变更→`stage-gate` 角色冲突** | `business-domain.ts` review-plan handler | 阶段变更需要 finance 会签时，会签通过后调用 `stage-gate` 的 actor 是 finance 角色，但 `stage-gate` 要求 `requireRole('pmo')`，导致 **阶段变更流程永远无法完成** |

### 🟡 中等问题（4 个）

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 2 | **`stage-gate` 可被直接调用绕过审批** | `business-domain.ts` | PMO 可直接调用 `stage-gate` 跳过完整的计划变更审批流程 |
| 3 | **未签额度在审批/审核时未重新检查** | `cost-orders.ts` approve、`labor.ts` review-labor | submit→approve 之间额度变化不会拦截 |
| 4 | **`budgetOverruns` 遗漏 SUB-04 子科目检查** | `budget-drafts.ts` | 期间费用子科目超概算不会被发现 |
| 5 | **财务会签可在评估阶段过早签署** | `changes.ts` finance-signoff-change | 会签到审批时可能已过时 |

### ⚠️ 轻微问题（3 个）

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| 6 | `submit-budget-draft` 递归调用 `transition` 导致双重 clone | `business-domain.ts` | 性能浪费 |
| 7 | 风险创建时 `rank` 参数校验但未使用 | `tickets.ts` create-ticket | API 设计混淆 |
| 8 | `actualHours` 在日报中无校验 | `reports.ts` save-daily | 可填负数 |

### ✅ 已确认无问题的领域

- 预算草稿→提交→审批→基线确认：**完整链路，分支正确**
- 成本订单提交→审批→履约→验收→入账：**完整链路，防重复机制有效**
- 工时填报→审核→入账：**完整链路，承诺消耗逻辑正确**
- 变更保存→提交→三方评估→PMO分级→审批→基线更新：**完整链路，任务/里程碑合并逻辑正确**
- 日报/周报：**完整链路，防重复提交有效**
- 事项创建→处理→关闭：**完整链路，状态机正确**
- 所有金额计算使用 `money()` 统一精度
- 所有 `percentage()` 有除零保护
- 所有 `allocateMoney()` 末项补余差
