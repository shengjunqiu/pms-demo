## 1. 链路一：结算差异归因

**要证明的事**：「项目赚了多少、差在哪、为什么差」在一页内自洽，且重大差异有据可查。
**台词**：「这个项目合同 5,538.30 万，最后滚动成本 2,986.20 万，超预算 138.50 万、4.9%。超在第三方费用和租房费用上，责任部门已经填了原因。」
**角色**：集团领导看结论 → 财务专员录原因。

| # | 操作 | 期望看到 | 依据 |
| --- | --- | --- | --- |
| 1.1 | 角色=集团领导，打开 `/executive/dashboard` | 首屏四卡为**滚动口径**：签约率 54/66、执行中 38、整体执行偏差、需关注项目数；下方「需关注项目」表在首屏可见，每行有健康度 + 主要风险原因文字 | BI-024/025 |
| 1.2 | 进入 `/projects/P-001/four-calculations` | 四算总览收入行 5,538.30（三列同值 + 注明「签约后锁定」）；「预算→最后滚动」列有科目级偏差，第三方费用 **+29.72（43.5%）**、租房费用 **+20.91（91.8%）** 转红 | JS-027/028/030 |
| 1.3 | 看首屏四卡 | 合同收入 5,538.30 / 最后滚动成本 2,986.20（副标「含承诺与预测」）/ 偏差 +138.50（副标「相对预算 4.9%」）/ 毛利率 46.1%；卡下口径等式 `1,650.00 + 836.20 + 500.00 = 2,986.20` | BI-025 |
| 1.4 | 切角色=项目经理(张建国)，看「维护差异归因」 | **可点击**（JS-031 授权角色为项目经理/财务/PMO） | JS-031 |
| 1.5 | 打开归因弹窗 | 每行卡头显示 `预算 / 最后滚动 / 偏差（%）`；命中「≥100 万或相对预算 ≥10%」的行标红并带「必填」 | 页面规则 `SettlementAnalysisPage` 阈值 |
| 1.6 | 空表直接确定 | 被拦住，错误信息**指名科目**，不是一句全局 toast | 错误预防 |
| 1.7 | 换收尾项目 P-008（收尾/项目结算，5 项重大差异未归因）：打开 `/projects/P-008/four-calculations` → 填完全部达阀科目 → 保存 | 保存成功；异常中心「归因未完成」计数下降，P-008 行的未归因文字消失 | JS-031 + `src/mock/alerts.ts` |
| 1.8 | 切角色=财务专员，重复 1.2 | 数字一致（不同角色看同一事实，不是各算一遍） | NFR-003 |

**实测结果**（2026-10-29，1.2/1.3/1.4 通过）：

- **1.4 已修**：`save-settlement-analysis` 已同时授予 `project-manager` 与 `pmo`（`src/mock/configuration-access.ts:21,24`），与 store 实际允许的角色（`src/mock/settlement.ts:95`「仅主PM、PMO或财务可维护差异归因」）一致。实测项目经理下按钮可用。残留：页面级角色表仍写「PMO、财务、管理层」（`src/routes/manifest.ts:1287`，JS-07），与 JS-031 不一致，需产品定口径。
- **1.7 已修（新链路）**：原来归因改完什么都不发生（八类健康度规则均不读 `settlementAnalysis`）。现在新增预警类型 `attribution`（`重大差异未归因`）：规则行 `ALERT-ATTRIBUTION-V1` 可配阀值/责任角色/渠道，评估在 `src/mock/alerts.ts`，阀值为**未归因差异合计占预算百分比**（默认提醒 3% / 严重 8%），只在**收尾/验收/已结算**项目上评估（执行期核算实际尚不完整，否则会把在途偏差全算成重大差异）。当前清单：P-006 6.29%、P-008 6.15% 为提醒，P-010/P-015/P-020/P-025/P-030/P-060/P-065 为严重，共 9 个。
- **1.6 现状（未修）**：弹窗 24 个 Select + 8 个 textarea 仍无必填标记，只能靠保存后被 store 拦住（报错已指名科目）；金额上下文只靠表格，「先记偏差再盲填」没完全解决。
- **D-05（新发现，未修）**：页面「差异」列与归因必填阀值用**两套口径** —— 页面 `variance = rolling − budget`（`SettlementAnalysisPage.tsx:127`），store 必填校验用 `actual − budget`（已获审计文档 `docs/验收结算关闭运维流程审计.md:140` 背书）。同一行可能页面标红却没进必填集，或反之。

## 2. 链路二：阶段切换门禁

**要证明的事**：「阶段有门、过门有据」——缺件时系统拦住，补齐后放行，且切换有记录。
**台词**：「他们这个阶段交付物还没审完，系统不让他们往下走。」
**角色**：项目经理提交 → PMO 审核与切换。

| # | 操作 | 期望看到 | 依据 |
| --- | --- | --- | --- |
| 2.1 | 角色=项目经理，打开 `/projects/P-001` | 阶段徽标「执行·开发实施」，右上「下一步：阶段切换申请」 | — |
| 2.2 | 点进 `/projects/P-001/stage-switch` | 表单带出来源阶段「执行/开发实施」与目标阶段「收尾 / 客户终验」，并列「校验条件 / 状态 / 校验依据」三列 | HS-16 / PRD 11.21.2 |
| 2.3 | 直接提交 | 若存在必交未通过项 → 拦截并列出具体缺项；不允许静默通过 | PRD §376、§3027 |
| 2.4 | 补齐/勾选后提交 | 生成审批单，状态进入「待 PMO 审核」，列表可见 | PRD 11.21.3 |
| 2.5 | 切角色=PMO负责人，审批该单 | 可以看到缺件校验结论（齐全/模板/阻断问题），通过后项目阶段变为「验收」 | PRD 11.21.3–11.21.4 |
| 2.6 | 返回 `/executive/dashboard` | 该项目阶段显示同步更新，执行中/验收计数变化 | 跨页状态 |

**实测结果**（2026-10-29）：**2.2/2.3 通过，且是本项目目前做得最好的一页** —— 五项校验逐条给结论与依据：「执行任务完成 · 阻断 · WBS整体62.5%，未完成3项」「必交材料审核 · 阻断 · 测试报告：缺失；验收确认函：缺失；实施计划：通过」；提交区另有行内提示「阶段门禁条件未全部满足，无法提交：执行任务完成、必交材料审核」（点名，不是一句「不满足条件」）；`提交PMO审批` 禁用且 `description` 暴露给读屏（`阶段门禁条件未全部通过，无法提交`）。**建议把这一页的写法定为其他门禁页的参照物。**

**待验点**（需 PMO 角色实测）：2.5 是否真的改变 `project.phase` 而非只改审批单；2.6 驾驶舱计数是否随之重算。

## 3. 链路三：字段权限与脱敏

**要证明的事**：敏感字段（收入/成本/毛利/人员评价）按角色隔离，且不可见的字段有明确说明而不是空白。
**台词**：「这个人看不到毛利，系统只给他看成本。」
**依据**：PT-047 字段权限、NFR-003 权限隔离、PRD §1286（成员看工时，PM 看汇总，财务看明细）。

| # | 操作 | 期望看到 | 依据 |
| --- | --- | --- | --- |
| 3.1 | 角色=方案架构师(赵工)，打开四算对比 | 毛利/毛利率区域显示「已脱敏」而非空白或 0.00，并有可读说明（tooltip 或行内文字） | PT-047 |
| 3.2 | 同角色打开 `/settings/permissions` | 字段权限矩阵中该角色 `margin` 未勾选，其余角色与矩阵一致 | PT-047 |
| 3.3 | 角色=集团领导，重复 3.1 | 毛利 2,552.10（不只是数字：口径标注仍在） | — |
| 3.4 | 直接访问该角色无权页面（如市场改 `/settings/permissions`） | 403 页面可读、给出下一步，不白屏 | 错误恢复 |

**实测结果**（2026-10-29）：

- **3.4 通过**：方案架构师直连 `/projects/P-001/four-calculations` 得到 `403 无访问权限 · 当前角色没有权限访问该页面或数据，请切换角色或联系管理员`，并给「返回可用页面」按钮。
- **3.1 不可达（D-02）**：`src/mock/configuration-access.ts:43` 的 `fields` 里，除 `solution-tech` 外 6 个角色全部包含 `margin`；而 `defaultPages['solution-tech']` 不含 `JS-07`（四算对比页），方案架构师直接被 403 挡在门外。**结果：唯一没有毛利权限的角色恰好进不了有毛利的页面 —— 演示里没有任何一个角色能看到「毛利已脱敏」。**
- 附带缺陷：页面把 `rate === null` 也判成「已脱敏」，会把「无合同收入」说成「权限隐藏」。
- 修复方向二选一：① 调整 `fields` 矩阵，让某个能进 JS-07 的角色（如 `project-manager`）不含 `margin`；② 演示词里删掉脱敏，同时把「已脱敏」分支改成 `null` 安全文案。
