# 导航结构优化设计

> 版本：V1.0（设计稿，未实施）
> 范围：全局侧边栏、顶栏、商机/项目工作区导航、页面内导航 Tabs、路由与面包屑规则。
> 不改变：72 页的业务能力、业务规则、权限白名单与 Mock 权威状态。业务口径仍以 docs 四份原文为准。

---

## 1. 背景

当前原型 72 页已全部实现，但页面之间的导航是逐页添加的，入口分散在 6 处独立定义中，使用时普遍感到"复杂、乱、不好找"。本设计统一导航的信息架构，目标是：

1. **一个页面只有一个"家"**：每页在导航体系中只有一个归属位置，其他位置只能作为上下文快捷链接，不能形成第二套导航。
2. **导航层级不超过 3 层**：全局菜单 → 工作区分组 → 页面。页面内 Tabs 只用于切换同一页的数据视图，不承担跨页导航。
3. **按"要做的事"组织，而非按"文档编号/阶段"组织**：生命周期阶段作为状态和下一步提示展示，不作为导航主轴。
4. **单一数据源**：菜单、工作区导航、面包屑、顶栏标题、高亮都从同一份导航配置生成。

## 2. 现状问题

### 2.1 导航定义分散（根因）

| 位置 | 作用 | 问题 |
|---|---|---|
| `src/routes/navigation.ts` `GLOBAL_NAV_SECTIONS` | 全局侧边栏 | 4 个分区各只有 1 个分组 |
| `src/components/layout/ProjectWorkspaceNav.tsx` `PROJECT_NAV_TABS` | 项目吸顶条，按阶段悬停下拉 | 与页面内 Tabs 重复 |
| `src/pages/budget/PlanningLayout.tsx` | 计划 8 个 Tabs | 与吸顶条"立项阶段"下拉完全重复 |
| `src/pages/execution/CostSourcesPage.tsx` `kindTabs` | 采购/外包/费用 Tabs | 与吸顶条"执行阶段"重复 |
| `src/pages/execution/ProjectOverviewPage.tsx` `tabs` | 项目总览 17 个 Tabs | 一半 Tab 只是独立页的缩略副本 |
| `src/routes/index.tsx` | 路由与硬编码跳过列表 | 新页面需同时改多处，易漏 |

### 2.2 项目内导航层叠

打开一个计划页（如 `/projects/P-001/wbs`）时，从上到下有 5 层导航：侧边栏 → 顶栏标题 → 项目吸顶条 → PageHeader（面包屑、重复标题、`navigate(-1)` 返回）→ PlanningLayout Tabs。用户无法判断应该用哪一层。

项目总览中，与成本相关的入口有"四算""成本""成本管理""项目成本"4 个 Tab，另有独立的"动态核算"页面；团队、计划进度、交付物、验收结算 Tab 与独立页内容重复。

### 2.3 阶段分组与使用习惯不符

- 执行期调整预算、团队时，需要到"立项阶段"下拉中找。
- 项目执行中最高频的**变更、需求/BUG、问题/风险**不在项目导航里，只能从全局菜单进入，或从总览 Tab 跳到 `/tickets?projectId=`。跳转后吸顶条仍显示，但没有任何项高亮，左侧菜单却高亮"事项管理"，上下文冲突。
- 下拉菜单仅支持悬停触发（`trigger={['hover']}`），键盘和触屏无法稳定使用；"验收结算"下挂 12 页，没有顺序或状态提示。

### 2.4 全局侧边栏

- 每个分区只有一个分组，因此"分区标题 + 分组标题"形成多余的一层。
- "业务台账与评审"一组混放了 7 项，且没有按业务流程排序（"提前投入"排在"立项评审"之后）。
- 菜单只有十几项，却额外提供了菜单搜索框，与顶栏 ⌘K 全局搜索重复。
- `DESIGN.md` 规定侧边栏可折叠到 64px，但代码中 `trigger={null}`，无法折叠。
- 同属"需要我处理"的事项被拆在三处：待办中心（WK-02，工作台分组）；待决策（WK-03）和异常中心（GL-05），都在经营分析分组。

### 2.5 孤立页面与路由不一致

| 问题 | 证据 |
|---|---|
| GL-04 组合分析在源码中无任何入口 | 全局搜索 `executive/portfolio` 仅命中路由定义 |
| GL-03 穿透分析只能从 GL-04/GL-05 进入，而 GL-04 本身没有入口 | — |
| JS-12 运维项目没有台账入口；访问时侧边栏高亮"项目台账" | `globalNavKey` 中的 `/operations/` 分支 |
| 同一事项页有 3 个 URL；`/tickets` 不在 manifest 中，顶栏标题退化为"项目管理平台" | `routes/index.tsx` |
| 财务配置有 4 个 URL 指向同一页，菜单入口 `/settings/finance-config` 不在 manifest 中 | `routes/modules/configuration-finance.tsx` |
| 商机没有工作区导航，项目有，体验不一致 | — |
| `globalNavKey` 中的 `/projects/…/reports` 分支不可达 | `navigation.ts` |
| 页面标题带编号（如"GL-03 项目穿透分析"），违反 DESIGN.md | `GL03ProjectDrilldownPage.tsx` |
| 用户菜单暴露开发用的"72页完整清单" | `MainLayout.tsx` |

## 3. 信息架构

整个应用分为三种导航上下文，任一时刻只处于其中一种：

```
┌─ 全局上下文 ──────────────────────────────────────────┐
│ 工作台、台账、经营分析、系统设置（无对象上下文也成立）       │
│   ├─ 进入某条商机 → 商机工作区（GS-03~GS-10）             │
│   ├─ 进入某个立项 → 立项评审上下文（YS-03、YS-04）         │
│   └─ 进入某个项目 → 项目工作区（HS/YS/JS 中带 :id 的页面） │
└──────────────────────────────────────────────────────┘
```

| 上下文 | 侧边栏 | 工作区导航条 | 面包屑 |
|---|---|---|---|
| 全局 | 显示并高亮当前项 | 无 | `首页 / 页面` |
| 商机工作区 | 高亮"商机台账" | 商机导航条 | `首页 / 商机台账 / 商机名 / 页面` |
| 立项评审 | 高亮"立项评审" | 无（页面较少，用面包屑） | `首页 / 立项评审 / 立项名 / 页面` |
| 项目工作区 | 高亮"项目台账" | 项目导航条 | `首页 / 项目台账 / 项目名 / 分组 / 页面` |

**规则**：工作区导航条只由路由路径（`/projects/:id/...`、`/opportunities/:id/...`）决定是否显示，**不再根据 `?projectId=` 查询参数显示**。查询参数只用于台账的预筛选。

### 4.2 交互规则

- 一级（分区）不可点击，只作为分组标题；二级为页面。去掉现有的"分区标题 + 同名分组"嵌套。
- 只显示当前角色有权限的项；整组无权限时隐藏该分区。
- 默认只展开当前页面所在的分区，其余分区收起，并记住用户的展开状态。
- 恢复折叠功能（240px ↔ 64px），折叠后以图标 + 悬浮浮层显示二级菜单。
- 删除侧边栏内的菜单搜索框，统一使用顶栏 ⌘K 全局搜索；全局搜索同时能搜到菜单页面名称。
- "72页完整清单"页面（`/routes-manifest`）从原型中整体移除：删除用户菜单入口、路由与页面组件。

## 5. 项目工作区

### 5.1 布局

项目工作区导航条吸顶在顶栏下方，分为两行：

```
┌──────────────────────────────────────────────────────────────────┐
│ ← 项目台账 │ [P-001 · 智慧园区… ▾]  执行中·实施  健康:关注   [下一步：阶段切换申请 →] │  ← 第1行：项目身份 + 阶段状态 + 下一步
│ 概览   计划   预算与成本   执行协作   验收结算   收尾                    │  ← 第2行：功能分组
│ ─────  团队 · WBS · 里程碑 · 计划评审 · 进度 · 基线                    │  ← 第3行：当前分组下的页面（仅分组>1页时显示）
└──────────────────────────────────────────────────────────────────┘
```

- **第 1 行**：返回台账、切换项目、当前阶段（`BusinessStageBadge` + `DeliveryStageBadge`）、健康度，以及**一个**"下一步"按钮。下一步按阶段门禁计算，例如未启动时为"启动确认"、执行中满足条件时为"阶段切换申请"、结算完成后为"项目关闭"。
- **第 2 行**：6 个功能分组，点击后进入该分组的第一个可访问页面。分组按钮支持键盘操作，不再使用悬停下拉。
- **第 3 行**：当前分组的页面链接，平铺显示，当前页高亮。可附带状态徽标（如"待审批""未提交"），状态只取自现有公共 selector，不在导航中新建业务事实。
- 原 `PlanningLayout` Tabs 和 `CostSourcesPage` 的 kindTabs 由第 3 行替代并删除。

### 5.2 分组与页面

| 分组 | 页面（按显示顺序） | 说明 |
|---|---|---|
| 概览 | HS-01 项目详情总览 | 单页，不显示第 3 行 |
| 计划 | YS-05 团队、YS-06 WBS、YS-07 里程碑、YS-08 计划评审、HS-02 进度、YS-12 基线 | 计划编制与执行进度放在一起 |
| 预算与成本 | YS-09 预算编制、YS-10 概预对比、YS-11 预算审批、HS-13 动态核算、HS-09 工时、HS-10 采购、HS-11 外包、HS-12 费用 | 四算中的"预算、核算"集中在此 |
| 执行协作 | 事项（项目内 HS-05/HS-07）、变更（项目内 HS-14/HS-15）、HS-03 日报、HS-04 周报、HS-17 交付物 | 新增项目内事项与变更入口 |
| 验收结算 | JS-01 内部验收、JS-02 供应商验收、JS-03 客户验收、JS-04 报验、JS-05 结算申请、JS-06 结算详情、JS-07 四算对比、JS-08 经营结果 | 按办理顺序排列 |
| 收尾 | JS-09 后评价、JS-10 资料归档、JS-11 运维衔接、JS-13 项目关闭 | JS-12 运维详情从 JS-11 进入 |

**阶段门禁页**（YS-15 启动确认、HS-16 阶段切换、JS-13 项目关闭）通过第 1 行的"下一步"按钮进入。其中 JS-13 同时列在"收尾"分组；YS-15 和 HS-16 不放进分组，只能从"下一步"和概览页的阶段卡片进入，避免同一入口出现两次。

分组内的页面按权限过滤；分组内全部不可访问时，隐藏该分组。

### 5.3 项目内事项与变更

新增项目范围路由，复用现有页面组件，并以路由参数锁定项目：

| 新路由 | 组件 | 说明 |
|---|---|---|
| `/projects/:id/tickets` | `TicketsPage` | 项目筛选锁定，不显示项目选择器 |
| `/projects/:id/tickets/:ticketId` | `TicketDetailPage` | 详情 |
| `/projects/:id/changes` | `ChangesPage` | 项目筛选锁定 |
| `/projects/:id/changes/new` | `ChangeFormPage` | 项目预填 |

全局 `/tickets`、`/project-changes` 继续作为跨项目台账。从全局台账点进某条记录时，仍打开全局详情 URL，侧边栏高亮全局台账，不显示项目导航条。现有指向 `?projectId=` 的项目内跳转改为指向新路由。

### 5.4 项目总览（HS-01）瘦身

17 个 Tabs 缩减为 **"一页摘要 + 5 个独有 Tab"**：

| 现有 Tab | 处理 |
|---|---|
| 项目概览 | 保留为首屏摘要 |
| 团队、计划进度、项目报告、协作事项、变更、交付物、验收结算 | **删除**，在摘要区改为对应分组的状态卡片，点击后跳转独立页 |
| 四算、成本、成本管理 | **合并**为摘要区的"四算卡片"（概算/预算/动态核算/结算），详细内容跳转 HS-13 动态核算 |
| 项目成本（`ProjectCostPanel`） | 保留为 Tab"成本核算表"；它对齐 BPM 核算表，含收入拆分与毛利口径，在其他页面没有对应内容 |
| 合同台账（`ContractLedgerPanel`）、回款 | 合并为 Tab"合同与回款" |
| 质量（`ProjectQualityPanel`） | 保留 |
| 未签管控 | 保留（仅未签项目显示） |
| 操作记录 | 保留 |

摘要区的状态卡片顺序与第 2 行分组一致：计划 → 预算与成本 → 执行协作 → 验收结算（收尾阶段暂无可汇总的公共数据，不设卡片）。每张卡片显示 2–3 个关键事实（例如"里程碑 3/8 · 1 项逾期"），数据只取自现有公共计算。

## 8. 统一导航配置

### 8.1 数据结构

新增 `src/routes/nav-config.ts`，作为菜单、工作区导航、面包屑、高亮和标题的唯一来源：

```ts
type NavContext = 'global' | 'opportunity' | 'initiation' | 'project';

interface NavNode {
  key: string;                 // 稳定 key，用于高亮与展开状态
  label: string;               // 导航显示名（不带编号）
  pageIds?: string[];          // 对应 manifest 页；用于权限与标题。多个时任一可访问即可见
  route?: string;              // 无 manifest 的聚合页，如 /projects、/tickets
  children?: NavNode[];
  aliases?: string[];          // 同页的其他路由，如 /requirements-bugs → 事项台账
  hidden?: boolean;            // 不在菜单显示，但参与高亮与面包屑（如详情页）
  parentKey?: string;          // hidden 页面高亮时指向的父节点
}

export const GLOBAL_NAV: NavNode[];        // 第 4 节
export const PROJECT_NAV: NavNode[];       // 第 5 节
export const OPPORTUNITY_NAV: NavNode[];   // 第 6 节

export function resolveNav(pathname: string): {
  context: NavContext;
  globalKey: string;           // 侧边栏高亮
  groupKey?: string;           // 工作区分组高亮
  pageKey?: string;            // 工作区页面高亮
  breadcrumbs: { title: string; href?: string }[];
  title: string;
};
```

### 8.2 替换关系

| 现有实现 | 替换为 |
|---|---|
| `GLOBAL_NAV_SECTIONS`、`globalNavKey` | `GLOBAL_NAV` + `resolveNav().globalKey` |
| `PROJECT_NAV_TABS` | `PROJECT_NAV` |
| `PlanningLayout` Tabs、`CostSourcesPage` kindTabs | 删除，由工作区第 3 行替代 |
| 顶栏 `currentPage.title` | `resolveNav().title` |
| 各页 `PageHeader` 手写 `breadcrumbs` | 默认取 `resolveNav().breadcrumbs`，页面仍可覆盖 |
| `routes/index.tsx` 硬编码跳过列表 | 由已注册路由集合自动计算 |

### 8.3 顶栏与 PageHeader 职责

- **顶栏**：⌘K 搜索、数据日期、演示角色、用户菜单。**不再显示页面标题**，避免与 PageHeader 重复。
- **PageHeader**：面包屑、页面标题（不带编号）、描述、页面操作。工作区内的"返回"按钮删除，由面包屑和工作区"← 台账"代替；表单页的"取消"保留。
- 标题统一去掉 `GL-03`、`YS-xx` 等编号前缀；编号只保留在 manifest 与清单页中。

### 10.1 验收场景

1. **单一归属**：遍历 72 个 manifest 路由（`demoRoute` 实例化），`resolveNav` 均返回唯一 `globalKey`；工作区页面返回唯一 `groupKey/pageKey`。
2. **角色可见性**：7 个角色切换后，侧边栏项与第 4.3 节矩阵一致，无空分组。
3. **项目链路**（项目经理，P-001）：项目台账 → 项目 → 计划/WBS → 预算与成本/采购 → 执行协作/事项 → 新建事项 → 返回。全程侧边栏高亮"项目台账"，导航条高亮正确，不出现两套 Tabs。
4. **全局与项目隔离**：从侧边栏进入事项台账，不显示项目导航条；从项目·执行协作进入，显示项目导航条，侧边栏高亮"项目台账"。
5. **下一步按钮**：P-001 不同阶段演示数据下，"下一步"指向的门禁页与阶段一致；无权限时不显示。
6. **旧链接兼容**：`/requirements-bugs`、`/issues-risks`、`/settings/cost-mapping`、`/projects/:id/procurement` 均能打开正确内容。
7. **键盘可达**：工作区分组与页面链接可用 Tab/Enter 操作，并有可见焦点。
8. **宽度**：1280 与 1440 宽度下，导航条不产生页面级横向溢出；1280 宽度下第 3 行允许换行。

改动影响已验收页面，实施后需对受影响页面做针对性回归，并按 AGENTS.md 在 `DEV_PROGRESS.md` 记录重开与重新验收的情况。
