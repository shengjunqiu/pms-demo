## 二、🔴 严重问题（3 个）

### #1: `update-forecast` 未加入 action 白名单

| 维度 | 说明 |
|------|------|
| **位置** | `src/mock/configuration-access.ts` — `ACCESS_ACTIONS` 白名单 |
| **问题** | 新增的 `update-forecast` action 未注册到白名单，`canAccessAction` 返回 false |
| **影响** | 项目经理在页面上点击"更新预测"时，权限校验失败，无法执行 |
| **修复** | 在 `ACCESS_ACTIONS` 数组中添加 `'update-forecast'` |

### #2: `review-plan` 阶段变更→`stage-gate` 角色冲突

| 维度 | 说明 |
|------|------|
| **位置** | `src/mock/business-domain.ts` — `review-plan` handler |
| **问题** | 阶段变更需要 finance 会签时，会签通过后调用 `stage-gate` 的 actor 是 finance 角色，但 `stage-gate` 要求 `requireRole('pmo')` |
| **影响** | 阶段变更流程永远无法完成（需要 finance 会签的场景） |
| **修复** | `review-plan` 中调用 `stage-gate` 时使用 PMO 角色，或 `stage-gate` 允许 finance 角色 |

### #3: `review-project-change` 未在 executive 白名单

| 维度 | 说明 |
|------|------|
| **位置** | `src/mock/configuration-access.ts` — 角色 action 白名单 |
| **问题** | `review-project-change` 未加入 executive 角色的白名单 |
| **影响** | 集团领导审批变更时被权限拦截 |
| **修复** | 在 executive 角色的 action 白名单中添加 `'review-project-change'` |

| 维度 | 说明 |
