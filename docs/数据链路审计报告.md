## 三、轻微缺陷（4 项）

### 3.1 qualityPlans — 通过函数间接访问，非直接字段引用 🟢

| 维度 | 说明 |
|------|------|
| **入口** | `quality-plan` action 创建 |
| **出口** | 通过 `qualityPlan()` 函数在 `DeliverablesPage.tsx` 中间接访问 |
| **问题** | 页面不直接引用 `data.qualityPlans`，而是通过 `qualityPlan(data, p.id)` 函数获取 |
| **影响** | 极小，函数封装是合理的设计模式 |

### 3.2 ticketMeta — 通过函数间接访问 🟢

| 维度 | 说明 |
|------|------|
| **入口** | `create-ticket`, `update-ticket`, `risk-to-issue` action 创建 |
| **出口** | 通过 `ticketMeta()` 函数在 `TodosPage` 和 `configuration-finance.ts` 中间接访问 |
| **问题** | 页面不直接引用 `data.ticketMeta` |
| **影响** | 极小，函数封装合理 |

### 3.3 constructionFreezes — 通过函数间接访问 🟢

| 维度 | 说明 |
|------|------|
| **入口** | `save-settlement` (submit=true) 时创建，`review-settlement` (amount-return/lock) 时删除 |
| **出口** | 通过 `constructionLockReason()` 和 `assertConstructionWritable()` 函数在多个 action 中检查 |
| **问题** | 无页面直接展示冻结状态 |
| **影响** | 极小，冻结是内部状态，通过 action 错误提示间接展示给用户 |

### 3.4 settlementForecastSnapshots — 仅内部使用 🟢

| 维度 | 说明 |
|------|------|
| **入口** | `dispose-settlement-balance` 时创建快照 |
| **出口** | 在 `settlementSnapshot()` 中读取，用于结算快照一致性比对 |
| **问题** | 无页面直接展示快照数据 |
| **影响** | 极小，快照用于结算锁定前的数据一致性校验 |

## 四、页面直接引用静态 Mock 数据的问题 🟡

以下页面直接引用静态 mock 变量而非通过 BusinessState 访问数据：

| Mock 数据 | 页面数 | 风险 |
|-----------|:-----:|------|
| mockUsers | 15 | 用户信息硬编码，切换角色/用户时可能不一致 |
| mockDepartments | 7 | 部门数据静态，无法反映动态变化 |
| mockProcurements | 3 | 历史采购数据静态，与 costOrders 可能不同步 |
| mockOutsources | 3 | 同上 |
| mockExpenses | 2 | 同上 |
| mockTimesheets | 2 | 历史工时数据静态 |
| mockCustomers | 2 | 客户信息静态 |
| mockCostSources | 2 | 成本来源凭证静态 |
| mockCostSnapshots | 1 | 历史成本快照静态 |

**影响**：这些静态数据与 BusinessState 中的动态数据可能不一致。例如，`mockProcurements` 中的采购记录与 `costOrders` 中的动态采购订单是两套数据源。

## 五、Action handler 存在但页面未直接 dispatch（5 项）

| Action | 原因 | 影响 |
|--------|------|------|
| `submit-budget` | 通过 `submit-budget-draft` 内部调用 | ✅ 正常 |
| `confirm-cost` | 内部 action，由 `process-cost-order` 和 `review-labor` 间接触发 | ✅ 正常 |
| `stage-gate` | 由 `review-plan` (stage 类型) 内部调用 | ✅ 正常 |
| `settle` | 明确抛出错误，禁止直接结算（须走完整结算流程） | ✅ 设计如此 |
| `close-issue` / `close-bug` | 被 `update-ticket` (confirm 操作) 替代 | 🟡 遗留 action，可考虑移除 |

## 六、建议

| 优先级 | 建议 | 工作量 |
|--------|------|--------|
| **P2** | 将 `mockUsers`/`mockDepartments` 等静态数据纳入 BusinessState，页面统一通过 store 访问 | 中 |
| **P3** | 移除 `close-issue`/`close-bug` 遗留 action（已被 `update-ticket` 替代） | 小 |
| **P3** | 移除 `settle` 遗留 action（已明确禁止直接结算） | 小 |
