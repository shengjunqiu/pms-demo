## 1. 商机→立项→项目 数据流

### 1.1 商机创建与评估

```
用户输入 → save-opportunity → Opportunity对象
  ├─ id, code, name, customerId, customerName
  ├─ ownerId, ownerName, departmentId, departmentName
  ├─ estimatedAmount, winRate, expectedSignDate
  ├─ status: '草稿' | '待评估' | '跟进中' | ...
  ├─ earlyInvestmentQuota, earlyInvestmentUsed
  ├─ createdAt, source?, projectType?
  └─ opportunityMeta[id]: { source, projectType, description, assessments[], ... }
```

**数据流路径：**
1. `save-opportunity` → 创建/更新 `Opportunity` + `OpportunityMeta`
2. `start-opportunity-assessment` → 创建评估轮次
3. `save-opportunity-dimension` → 各角色填写维度评分
4. `conclude-opportunity` → 更新商机状态（拟立项/暂缓/已终止）

**字段映射：**
- `OpportunityInput` → `Opportunity`（基础字段）+ `OpportunityMeta`（扩展字段）
- `DimensionOpinion` → `round.opinions[key]`

**✅ 数据流完整**

### 1.2 提前投入

```
save-early-investment → EarlyInvestmentRequest
  ├─ opportunityId, amount, startDate, endDate
  ├─ status: '草稿' | '待审批' | '通过' | '驳回'
  └─ 审批通过后 → o.earlyInvestmentQuota += amount

record-early-cost → EarlyCostRecord
  └─ 正式立项后 → inheritEarlyCosts() 继承到项目
```

**数据流路径：**
1. 提前投入申请 → 审批 → 更新商机额度
2. 登记前期成本 → 归集到商机
3. 立项通过 → `inheritEarlyCosts()` → 成本继承到项目

**✅ 数据流完整**

### 1.3 概算编制与冻结

```
estimate-create-draft → EstimateDraft（从通过评审生成）
estimate-save-draft → 更新草稿
estimate-publish → EstimateVersion（未冻结）
estimate-freeze → EstimateVersion.isFrozen = true
  └─ o.currentEstimateVersionId = estimate.id
```

**数据流路径：**
1. 方案评审通过 → 生成概算草稿（引用 `reviewId`, `solutionVersionId`, `costVersionId`）
2. 发布 → `EstimateVersion`（`isFrozen: false`）
3. PMO 冻结 → `isFrozen: true`，`o.currentEstimateVersionId` 指向冻结版本

**字段映射：**
- `EstimateDraft.lines` → `EstimateVersion.items`（按 subjectId 汇总）
- `estimateTotals(draft)` → `totalIncome, totalCost, grossMargin, grossMarginRate`

**✅ 数据流完整**

### 1.4 立项申请与决策

```
save-initiation → InitiationApplication（草稿）
submit-initiation → 创建 InitiationRound
  ├─ initiationSource() → 收集商机、概算、方案、评审、风险
  └─ 状态: '待风险评估'

assess-initiation-risk → PMO 风险评估
classify-initiation → 项目分级 + 确定决策路径
sign-initiation → 线上会签（6 节点）
decide-initiation → 决策结果
  ├─ '通过' → createInitiatedProject() → 创建 Project
  ├─ '整改' → 整改后重新提交
  ├─ '否决' → o.status = '已终止'
  └─ '暂缓' → o.status = '暂缓'
```

**数据流路径：**
1. 提交 → `initiationSource()` 收集：商机 + 冻结概算 + 方案版本 + 专家评审 + 风险
2. 风险评估 → PMO 确认风险等级
3. 分级 → 确定项目级别（一般/重点/重大/特大型）和决策路径
4. 会签/决策 → 通过则创建项目

**关键字段映射：**
- `InitiationRound.source` ← `initiationSource()`: 包含 `opportunity`, `estimate`, `solutionVersionId`, `expertReviewId`, `risks`, `earlyCostTotal`
- `createInitiatedProject()` → `Project`: 继承商机信息、概算、提前投入成本

**✅ 数据流完整**

## 2. 四算联动数据流

### 2.1 概算→预算

```
概算: EstimateVersion（商机阶段，立项前冻结）
  │
  ├─ budgetOverruns(budget, estimate) → 检查是否超概算
  │    ├─ 总成本超过概算
  │    └─ 主要科目超过概算阈值
  │
  └─ 预算审批通过后 → confirmBudgetBaseline()
       ├─ 创建 BudgetVersion（status: '已生效'）
       ├─ 创建 BaselineVersion（status: '已生效'）
       └─ p.budgetAmount = budget.totalAmount
```

**数据流路径：**
1. 预算编制 → `BudgetDraft` → `toBudgetVersion()` → 提交审批
2. 审批 → `submit-budget` → `Approval`（待审批）
3. 审批通过 → `BUD-PENDING-{id}`（待确认）
4. PMO 确认 → `confirm-budget-baseline` → 预算生效 + 基线生效

**字段映射：**
- `BudgetDraft.lines` → `toBudgetVersion()` → `BudgetVersion.items`（按 subjectId 汇总）
- `confirmBudgetBaseline()` → `BudgetVersion.status = '已生效'` + `BaselineVersion.status = '已生效'`
- `p.budgetAmount = budget.totalAmount`
- `p.currentBaselineVersion = version`

**✅ 数据流完整**

---

### 2.2 预算→核算

```
预算: BudgetVersion（目标成本基线）
  │
  ├─ 成本订单审批通过 → adjustCommitment() → p.commitmentBySubject
  ├─ 成本订单入账 → p.actualCost += amount
  ├─ 工时入账 → p.actualCost += amount
  └─ 结算处置 → p.forecastBySubject 更新

核算: selectFourCalculations() → 实时计算
  ├─ subjects[]: 按科目汇总 estimate/budget/actual/committed/remaining/rolling
  ├─ actual: sum(costs)
  ├─ rolling: actual + committed + remaining
  └─ variance: rolling - budget
```

**数据流路径：**
1. 成本订单提交 → `submit-cost-order` → `CostOrder`（待审批）
2. 财务审批 → `process-cost-order(approve)` → `adjustCommitment()` → 增加承诺
3. 履约验收 → `process-cost-order(accept)` → 更新状态
4. 财务入账 → `process-cost-order(book)` → `p.actualCost += amount` + 创建 `CostItem`
5. 工时入账 → `review-labor` → `p.actualCost += amount`
6. 结算处置 → `dispose-settlement-balance` → 更新 `p.forecastBySubject`

**关键计算：**
- `p.rollingCost = p.actualCost + p.committedCost + p.forecastRemainingCost`
- `p.costVariance = p.rollingCost - p.budgetAmount`
- `p.costVarianceRate = percentage(costVariance, budgetAmount)`

**✅ 数据流完整**

---

### 2.3 核算→结算

```
核算: 实时成本（actualCost + committedCost + forecastRemainingCost）
  │
  ├─ save-settlement → SettlementRequest（草稿）
  │    ├─ settlementSnapshot() → 冻结当前快照
  │    └─ 包含: estimate/budget/baseline 版本 + 成本 + 合同 + 回款
  │
  ├─ review-settlement(finance-confirm) → 财务核算确认
  ├─ review-settlement(pmo-audit) → PMO 审核
  ├─ review-settlement(review-pass) → 结算评审通过
  └─ review-settlement(lock) → 最终锁定
       ├─ 创建 SettlementRecord（status: '已锁定已生效'）
       ├─ p.status = '已结算', p.phase = '收尾'
       └─ state.lockedProjects.push(projectId)
```

**数据流路径：**
1. 提交结算 → `settlementSnapshot()` 冻结快照（包含所有版本引用）
2. 财务确认 → 记录开票金额和税费
3. PMO 审核 → 检查材料完整性
4. 结算评审 → 组织评审会议
5. 最终锁定 → 检查快照未变化 → 创建正式结算记录

**关键检查：**
- `settlementChecks()`: 客户验收确认、成本已明确、无重复结算、重大事项已处理
- 锁定前检查：快照成本/收入/版本未变化

**✅ 数据流完整**

## 3. 执行→变更 数据流

### 3.1 变更申请与审批

```
save-project-change → ChangeRequest（草稿）
  ├─ proposeChange() → 计算提议基线
  └─ 创建 ProjectChange 摘要记录

submit-project-change → ChangeRequest.status = '影响评估中'
  └─ ProjectChange.status = '影响评估中'

assess-project-change → 技术/财务/市场 专业评估
  └─ 三方评估完成 → status = '待分级'

classify-project-change → PMO 分级
  ├─ 确定 requiredRole（pmo/executive）
  └─ status = '待审批'

review-project-change → 审批
  ├─ 通过 → confirmBudgetBaseline() → 新基线生效
  │    ├─ 更新 WBS 任务
  │    ├─ 更新里程碑
  │    ├─ 更新项目工期/收入
  │    └─ 更新项目团队
  └─ 驳回 → status = '驳回'
```

**数据流路径：**
1. 保存草稿 → `ChangeRequest` + `ProjectChange` 摘要
2. 提交 → 影响评估中
3. 三方评估（技术/财务/市场）→ 待分级
4. PMO 分级 → 待审批（PMO 或 PMC）
5. 审批通过 → `confirmBudgetBaseline()` → 新基线生效

**字段映射：**
- `ChangeInput` → `ChangeRequest.input`
- `proposeChange()` → `ChangeRequest.proposed`（`FullBaselineSnapshot`）
- `confirmBudgetBaseline()` → 新 `BaselineVersion` + 更新 `Project` 字段

**✅ 数据流完整**

## 4. 验收→回款 数据流

### 4.1 验收流程

```
submit-acceptance → AcceptanceRecord（待验收）
  ├─ acceptanceConditions() → 检查前置条件
  └─ 创建 AcceptanceDetail

review-acceptance → 验收检查
  ├─ 通过 → AcceptanceRecord.status = '已通过'
  │    ├─ 供应商验收 → 更新 CostOrder.status = '验收通过'
  │    └─ 客户终验 → 等待 PMO 确认
  └─ 不通过 → status = '整改中' + 创建整改项

reply-acceptance → 主PM 回复整改
confirm-acceptance → PMO 确认客户验收
  └─ 联动: 回款计划标记 '【待收款】'
```

**数据流路径：**
1. 提交验收 → 检查前置条件（WBS 完成、BUG 关闭、材料齐全等）
2. 验收检查 → 逐项填写检查结果
3. 通过 → 更新状态 + 供应商验收联动 CostOrder
4. 客户终验 PMO 确认 → 回款计划联动

**✅ 数据流完整**

---

### 4.2 回款流程

```
confirm-project-receipt → ReceiptRecord
  ├─ 检查: 合同关联、流水号唯一、金额精确
  ├─ 分配: 按 ReceiptPlan 分配金额
  ├─ 更新: plan.paidAmount += amount
  └─ 更新: contract.paidAmount += amount, unpaidAmount -= amount
```

**数据流路径：**
1. 财务登记回款 → 选择合同 + 回款计划
2. 分配金额 → 更新各回款节点实收
3. 更新合同实收/未收

**✅ 数据流完整**

## 6. 成本归集数据流

### 6.1 成本订单流

```
submit-cost-order → CostOrder（待审批）
  ├─ 检查: 生效基线、科目匹配、预算可用、未签额度
  └─ checkLimit() → 检查科目预算 + 未签额度

process-cost-order(approve) → 财务批准
  ├─ adjustCommitment() → 增加承诺
  └─ CostOrder.status = '已批准'

process-cost-order(progress) → 履约进展
process-cost-order(accept) → 验收通过
  └─ CostOrder.status = '验收通过'

process-cost-order(book) → 财务入账
  ├─ adjustCommitment() → 减少承诺
  ├─ p.actualCost += amount
  ├─ 创建 CostItem
  └─ CostOrder.status = '已入账'
```

**关键计算：**
- `costAvailability()`: `budget - actual - committed - pending`
- `adjustCommitment()`: 更新 `p.commitmentBySubject[subjectId]`
- 入账后: `p.rollingCost = actual + committed + remaining`

**✅ 数据流完整**

### 6.3 结算处置流

## 7. 未签项目跟踪数据流

```
unsignedControl() → UnsignedProjectControl
  ├─ initiatedAmount, initiatedAt, expectedSignDate
  ├─ validUntil, ruleVersion
  ├─ autoBlocked?
  └─ followups[]

unsignedSummary() → 未签状态摘要
  ├─ exposure: actualCost + committedCost + pendingCost
  ├─ quota: unsignedLimitQuota
  ├─ usage: percentage(exposure, quota)
  └─ flags: ['签约逾期', '投入超限', '长期未签', ...]

follow-unsigned → 更新跟进记录
request-unsigned-investment → 申请追加额度
confirm-project-contract → 确认签约
exit-unsigned → 退出未签
```

**数据流路径：**
1. 立项通过（未签）→ `p.isUnsigned = true`
2. 未签跟踪 → `unsignedSummary()` 计算暴露额度
3. 跟进 → `follow-unsigned` 更新进展
4. 追加额度 → `request-unsigned-investment` → 审批 → `p.unsignedLimitQuota = proposedQuota`
5. 签约 → `confirm-project-contract` → 创建合同 + 回款计划
6. 退出 → `exit-unsigned` → 终止未签

**⚠️ 已知问题：**
- `autoBlocked` 字段已存在但业务逻辑未检查
- `assertNewProjectCommitment()` 检查未签额度但未使用 `autoBlocked`
