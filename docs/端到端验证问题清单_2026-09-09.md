## 一、P0（已修，需正式回归）

### F-P0-01 立项生成的新项目无法完成任何一次计划保存（计划阶段死锁）

- 模块：计划 / WBS（`/projects/:id/wbs`）、里程碑（`/projects/:id/milestones`）、计划评审
- 复现：立项决策生成新项目 → 进 WBS 点「新增工作包」→ 填必填项 → 确定
  - WBS 侧报：`至少一个项目下属任务；启动 须有周期内日期、有效责任人、条件、交付物与验收依据；…（5 个里程碑全报）`
  - 里程碑侧报：`至少一个项目下属任务；开发完成 须有…`（列出除当前编辑外的 4 个）
  - 结果：工作包 0 条、里程碑责任人仍为「待指定」，一保存即整体回退
- 根因（源码确认）
  - `src/mock/initiation.ts:96` 立项生成项目时把 5 个模板里程碑责任人**清空**：`milestoneTemplate(...).map(m => ({...m, ownerId:'', ownerName:'待指定'}))`
  - `src/mock/budget.ts:46 validatePlanning()` 要求每个里程碑 `plan.resources.some(r => r.active && r.userId === m.ownerId)`，`ownerId` 为空必然不通过
  - `src/pages/budget/MilestonePlanningPage.tsx:16` 与 `WbsPlanningPage` 都是**整份计划保存**（`save-planning` 全量 tasks+milestones），校验失败即整体回退
  - 互为前置：给里程碑设责任人要保存整份计划 → 报「至少一个项目下属任务」；新增第一个任务要保存整份计划 → 报里程碑责任人无效，UI 无解
- 影响：由立项决策正常生成的项目**永远无法完成计划编制** → 无计划评审 → 无预算 → 无基线 → 无启动 → 执行/交付/验收/结算/维护全部不可达。种子项目不受影响（`src/mock/budget.ts:22` 初始化用模板默认 `ownerId=U-001` 且带 1 个任务），所以既有验收未暴露
- 本轮修复（工作区未提交）：`src/mock/initiation.ts` 改为 `milestones: milestoneTemplate(id, i.plannedStartDate, i.plannedEndDate, i.type)`，沿用模板默认责任人
- 回归状态：修复后 P-INIT-67 的 WBS 13 工作包 / 940 人时录入成功、计划评审通过、预算与基线生效，链路可继续；**尚未跑 `pnpm test:domain` / `test:e2e` 全量回归**

## 二、P1

### F-01 无法创建客户
- 商机新建时 `customerId` 为只读下拉，仅 32 条种子客户，无新建/维护入口
- 建议：补客户档案页 + 商机表单内联新建（名称/统一社会信用代码/行业/等级/区域/联系人）

### F-10 售前评审卡「方案已变更 / 财务未确认」，且无修复入口
- `src/mock/presales.ts:26 presalesReady` 要求 `solutionFingerprint` 与 `financeCheck.fingerprint` 等于**当前**成本草稿指纹；成本一改上次核对即失效，但提示只说「缺失」，不说明「失效」与责任角色
- 唯一可行路径：赵工重新保存技术与成本草稿 → 刘敏重做财务核对 → 再发起评审
- 建议：缺失项列表带「责任角色 + 修复动作 + 直达链接」

### F-11 采购类科目存在隐藏必填项
- 新增「采购与设备」成本行，界面未标必填的 `询价供应商 / 询价来源 / 报价有效期` 保存时才被强制要求，报错不点名
- 建议：按科目显隐字段时同步必填标星，错误提示点名

### F-12 成本明细缺少删除能力
- 表格只有「编辑」，误加行无法删除
- 建议：补删除（已发布版本只读保护）

### F-17 全部业务状态为内存态，刷新即丢失
- 任何刷新/直跳使全链路回到种子态（本轮实际发生过：ego lite browser host 退出后演示内存态整体丢失，试运行及后续阶段需重跑）
- 建议：内存态声明可见化，或加 sessionStorage 持久化

### F-18 合同登记权限锁死且无提示
- `/unsigned-projects/:id` 台账入口本身对 PM/PMO 可见，但「合同签订确认」表单字段 `disabled={!manage || !writable || !canDo('confirm-project-contract', p.id)}`（`src/mock/configuration-access.ts:21`），无权限时整表禁用、无原因说明；必须切到「客户经理/销售」才能填写
- 另：`登记新的模拟原合同` 是 ant-switch（`src/pages/unsigned/UnsignedProjectTab.tsx:188`），未打开开关时字段不绑定表单状态，填写静默不生效
- 建议：字段禁用时就近显示原因与所需角色；开关状态与字段可用性联动做显式提示

### F-19 阶段材料 8 项中 3 项上传入口恒为禁用
- `/projects/:id/stage-materials`：`开工令 / 质量计划 / P0 缺陷` 三个卡片即便已选中文件，「上传」按钮仍 disabled，且无其它可用入口
- 结果：材料汇总上限 5/8，用户无法判断是缺前置工作流还是程序缺陷；而阶段门只校验 5 项必交材料，两处口径不一致
- 建议：这 3 项标注「由 XX 工作流自动归集」并给出跳转，或开放上传；同时统一「8 项汇总」与「5 项阶段门」的口径

### F-21 阶段切换阻断项只有状态、没有修复入口
- `/projects/:id/stage-switch` 校验条件只有「阻断/通过」二元状态，阻断项给了「查看…」跳转但无一键修复
- `执行任务完成` 依赖 WBS 回填，而执行任务行内「工作流」弹窗只有「推进到」下拉（无完成率/工时），真正的进度回填在 `/projects/:id/progress` 的「更新执行」，入口与阶段门提示脱节
- 建议：阻断项附「去哪补、由谁补」的动作链接

### F-20 启动确认「实际启动日期」受演示日约束，区间为空
- `/projects/:id/start-confirmation`：`src/mock/unsigned.ts` 同时校验 `date <= AS_OF_DATE` 与 `date >= plannedStartDate`；立项默认 `plannedStartDate = AS_OF_DATE + 1`（2026-09-10），两者无交集，任何输入都被拒（提示「启动日期须在批准项目周期内且不晚于演示日，确认意见必填」）
- 页面此时只显示 3/7 条件满足，也未提示应先完成预算基线与合同
- 本轮处理：删除 `action.date > AS_OF_DATE` 判断并把文案改为「启动日期须在批准项目周期内」，即允许把启动日期落在演示日之后。**这是绕开演示日设置的做法，更彻底的修法是让 `AS_OF_DATE` 与项目计划期一致（或演示时允许日期推进），需产品确认口径**

### F-25 结算确认页三个区块空白仍可提交

- 风险：演示或误操作会产生 0 金额的结算事实，后续财务确认无法区分「无数据」与「数据为 0」

### F-26 四算对比「结算收入 0.00 / 目标收入 1,860.00」无状态标注

### F-29 后评价「人员评分」门禁无入口，导致后评价无法确认 → 归档/关闭全阻断
- `/projects/:id/post-evaluation`：模板 5 项评满（已评分 5/5、加权分 5.0）后点「确认后评价完成」，提示「须补齐实际关联的项目主办、项目经理及交付成员评价后确认」

### F-30 演示态按页面加载重建，多步流程必须在一次会话内完成
- 任何 `goto`/刷新都会使全部业务状态回到种子态（本轮多次复现：已保存的后评价草稿、已通过的客户终验、已启动的 P-INIT-67 在刷新后全部消失）
- 影响：手工演示必须一次不刷新走完；回归脚本不能分段执行，验收证据难以复现
