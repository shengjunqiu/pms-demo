## 0. 开场必读（三条铁律 + 两条口径）

**铁律一：一次不刷新，走完一段。**
演示环境是内存态 Mock。任何 `F5`、地址栏直接输入 URL、浏览器后退、关闭标签页重开，都会把全部业务状态打回种子态（问题清单 **F-30**／F-17）。段内所有跳转一律用**页面上的链接、页签、按钮**，不要用地址栏。切身份用页头右上角「角色:」下拉，**SPA 内切换不刷新、状态保留**。

**铁律二：基准日固定 2026-09-09。**
页头固定显示「截至 2026-09-09」。所有日期、预警天数、到期提醒都以此为准，演示中不要口头改成"今天"。

**铁律三：只有 7 个身份。**
页头「角色:」下拉里只有这 7 个（`src/store/useAppStore.ts` 的 `ROLES`）：集团领导(王总)、PMO负责人(李主任)、项目经理(张建国)、客户经理/销售(陈亮)、财务专员(刘敏)、方案架构师(赵工)、系统管理员(Admin)。**没有"客户""运维工程师""评审专家"这类登录身份**——客户验收由项目经理登记、运维由 PMO 代办、专家评审由赵工/刘敏分别以"技术专家/财务专家"身份填写。

**口径一：身份的"项目经理"只有一个账号。**
`项目经理` 这个身份永远是 **张建国（U-001）**。某个项目的"主项目经理"是别人的话（例如 P-004 的主 PM 是刘敏），页面上就**只有 PMO 能办该项目的启动/计划事项**，切到张建国会看到 403 或按钮全灰。剧本里已经按这个事实排好了身份顺序。

**口径二：切身份可能把页面带走。**
平台切角色时会判断"新角色能不能看当前页"，不能看就跳回该角色首页（财务→四算分析、方案架构师/客户经理→商机台账、项目经理→工作台、PMO/集团领导→项目看板）。剧本中每次切身份都写了"切完停在哪"，若发现被带走，就按剧本给的菜单再点回来。

**讲解话术（4 句）**

1. "这条商机预计 2,600 万，成本按 1,560 万测算，毛利 1,040 万、40%——但它今天还不能立项，因为系统卡了三个门：方案、成本、冻结概算。"
2. "方案定范围、成本定钱，两份材料被评审冻结成 V1，之后的任何修改只能追加版本，不能盖掉评审时的快照。"
3. "决策会不是一个人说了算：PMO 先出结论，重大或高风险项目必须再上集团领导，第一级点完项目不会生成，第二级点完才落项目——这叫'节点内未全部通过不生效'。"
4. "所以立项不是一张审批单，是一条链：商机→方案→成本→评审→概算→决策，每一环都有版本、有签字人、能倒查。"

> **可选加演（+8 分钟，不进主线）**：想演示"六维初评→拟立项"的真实编制，用 OPP-073（海州市智慧交通信号优化平台，2,860.00 万，跟进中）：商机台账打开→「办理⌄ → 发起评估」→ 六维逐一「填写意见」（客户价值/商务风险/竞争态势由陈亮填，技术可行性/交付难度由赵工填，收益与毛利由刘敏填初步成本）→ 填「综合决策原因」→「确认拟立项」。

**已知风险与兜底**

- **F-10**：方案或成本一改，财务核对指纹失效，评审就卡在"材料未齐"。本段方案/成本都是冻结态，不会触发；加演时若改动成本，必须回到「财务成本核对」重新「确认当前测算」。
- **F-11 / F-12**：加演新增"采购与设备"成本行时，`询价供应商 / 询价来源 / 报价有效期`是隐藏必填，报错不点名；成本行只能编辑，不能删。
- **F-14**：概算页可能同时存在"发布态 V1"和"冻结态 V2"，只认 `已冻结` 那个，别指着草稿讲。
- 若第二节点按钮仍停在第 1 节点（PMO 已点但节点没前进）：**改为演示 INIT-3**（一般项目，六节点会签已完成、待决策，PMO 一节点即可通过）——`立项评审 → INIT-3 → 进入评审决策 → 通过当前节点`。
- 若决策时被拦"当前角色不是本节点审批人"：说明当前节点还没轮到该角色——看页面「当前节点」是 1/2 还是 2/2 再切人（**不要刷新**，刷新会丢掉整条链，改为退出立项评审重新进入）。

**验证状态**：✅ 已验证（商机初评→方案→成本→评审→概算冻结→立项决策→生成项目，见问题清单第五节第 1–3 项）。其中"PMC 两节点决策链"未单独留证，验证过的是六节点会签路径（第五节第 3 项），风险与兜底已给替代路线。
