> 涉及角色：财务专员（刘敏）、PMO负责人（李主任）

```mermaid
graph TB
  FROM_ACCEPT(["来自验收完成"]) --> START

  subgraph SETTLEMENT["结算流程"]
    direction TB
    START[建设期成本锁定] --> S1[财务结算审核]
    S1 --> S2[PMO结算确认]
    S2 --> S3[项目结算评审]

    S3 --> R{评审结果}
    R -->|通过 ✅| CLOSE[项目关闭]
    R -->|不通过 ❌| FIX[整改后重新结算]
    FIX --> S1
  end

  subgraph CLOSURE["项目关闭后"]
    direction TB
    CLOSE --> TYPE{项目类型判断}

    TYPE -->|运维服务类| OPS[进入运维质保期]
    TYPE -->|非运维类| ARCHIVE[归档结束]

    OPS --> OPS1[质保运维执行]
    OPS1 --> OPS2[运维期满]
    OPS2 --> ARCHIVE
  end

  subgraph ROLES["角色职责"]
    R1["👤 财务专员（刘敏）<br/>成本锁定、结算审核"]
    R2["👤 PMO负责人（李主任）<br/>结算确认、评审组织"]
  end

  R1 -.-> S1
  R2 -.-> S2
  R2 -.-> S3

  %% 问题标注
  CLOSE -.->|"⚠️ 结算→运维<br/>衔接机制不明确"| ISSUE1
```

## 说明

- **结算流程：** 建设期成本锁定 → 财务结算审核 → PMO 结算确认 → 项目结算评审
- **项目关闭后：** 运维类项目进入质保期；非运维类项目归档
- **已结算示例：** P-008 某县数据中台建设项目（预算 1,450万，已结算 1,390万，结余 +60万）
- **问题：** 结算→运维的切换机制不明确，运维阶段的启动条件未清晰定义
