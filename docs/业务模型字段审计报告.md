## 二、缺失字段（业务流程需要但接口中不存在）

### 2.1 Project 接口

| # | 缺失字段 | 业务理由 |
|---|----------|----------|
| M1 | `description?: string` | 项目详情页无项目描述/概述区域 |
| M2 | `createdAt: string` | 项目台账无法按创建时间排序或筛选 |
| M3 | `maintenanceEndDate?: string` | 运维项目需要记录质保到期日期 |
| M4 | `warrantyStatus?: '质保中'\|'已到期'` | 运维项目需要跟踪质保状态 |
| M5 | `estimatedRevenue?: number` | `revenueAmount` 语义过载（同时承担"预计收入"和"未签拟签金额"） |

### 2.2 Contract 接口

| # | 缺失字段 | 业务理由 |
|---|----------|----------|
| M6 | `contractType?: '一般合同'\|'框架合同'\|'补充协议'` | `ContractLedgerBasic` 已有，`Contract` 没有 |
| M7 | `signOrg?: string` | 签约主体，`ContractLedgerBasic` 已有 |
| M8 | `industry?: string` / `region?: string` | `ContractLedgerBasic` 已有 |
| M9 | `execStatus?: '在建'\|'已完工'\|'已验收'\|'已结算'\|'已终止'` | `Contract.status` 粒度不够 |
| M10 | `departmentId/departmentName` | 合同台账无法按部门筛选 |
| M11 | `pmId/pmName` | 合同详情无法直接显示项目经理 |

### 2.3 Opportunity 接口

| # | 缺失字段 | 业务理由 |
|---|----------|----------|
| M12 | `source?: string` | `OpportunityMeta` 有 `source`，但商机列表页无法直接展示 |
| M13 | `projectType?: string` | `OpportunityMeta` 有 `projectType`，但商机列表页无法直接展示 |

### 2.4 其他接口

| # | 接口 | 缺失字段 | 业务理由 |
|---|------|----------|----------|
| M14 | `Project.subPhase` | 缺少 `'运维交接'`、`'后评价'`、`'归档'` | `phase` 有 `'收尾'`，但 `subPhase` 没有对应的收尾子阶段值 |

| M18 | `AcceptanceRecord` | `createdAt: string` | 验收记录无法按时间排序 |
| M19 | `AcceptanceRecord` | `submittedBy: string` | 无法追溯谁发起了验收 |
| M20 | `WbsTask` | `actualHours?: number` | 工时管理需要任务级别的实际工时 |

| M22 | `SettlementRequest` | 各步骤独立时间戳 | 结算流程 4 步缺少每个步骤的时间戳字段 |
| M23 | `UnsignedProjectControl` | `autoBlocked?: boolean` | 未签超限后无自动熔断机制 |
| M24 | `ChangeRequest` | `financeSignoff?: boolean` | 成本变更缺少独立"财务会签"审批步骤 |

## 三、状态/命名不一致

| # | 问题 | 详情 |
|---|------|------|
| I1 | `ProjectChange.status` vs `ChangeRequest.status` | `ProjectChange` 用 `PMO审批中/PMC审议中`，`ChangeRequest` 用 `影响评估中/待分级/待审批`。同一业务两个状态集 |
| I2 | `DailyReport.status` vs `WeeklyReport.status` | `已提交` vs `已上报`，语义相同但拼写不同 |
| I3 | `DailyReport.spentHours` vs `WbsTask.plannedHours` | 日报用 `spentHours`（实际工时），WBS 用 `plannedHours`（计划工时），命名不统一 |
| I4 | `Project.rollingCost` vs `SettlementSnapshot.lastRolling` | 同一概念命名不同 |
| I5 | `Contract` vs `ContractLedgerBasic` 字段分裂 | `Contract` 10 个字段，`ContractLedgerBasic` 20+ 字段，两套数据可能不同步 |
| I6 | `ReceiptPlan.paidAmount` vs `Contract.paidAmount` 重复 | 两个接口都有实收金额，缺少自动同步机制 |
| I7 | 流程图 vs 代码：变更类型不一致 | 流程图显示 4 种类型，代码已简化为 3 种（流程图未更新） |
