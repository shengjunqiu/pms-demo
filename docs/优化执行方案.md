## 3. 批次与依赖关系

```mermaid
graph TD
    subgraph 第一批[第一批 · 高优先级]
        A[日报+周报合并] --> M1[协调者: 路由/导航/项目页]
        B[采购/外包/费用合并] --> M1
    end
    
    subgraph 第二批[第二批 · 中优先级]
        C[四台账合并] --> M2[协调者: 路由/导航/项目页]
        D[未签台账合并] --> M2
    end
    
    subgraph 第三批[第三批 · 低优先级]
        E[变更类型简化] --> M3[协调者: 类型定义/路由]
        F[财务配置合并] --> M3
    end
    
    M1 -.->|第一批合入后| M2
    M2 -.->|第二批合入后| M3
```

**关键规则**:
- 每批内两个任务互不依赖，可完全并行
- 每批之间串行（合入 + 回归后再启动下一批）
- 协调者负责所有共享文件的修改，开发者不碰共享文件

## 6. Git 工作流

```mermaid
graph LR
    subgraph main[main 分支]
        M0[基点: 0ccf13a]
        M1[第一批合入]
        M2[第二批合入]
        M3[第三批合入]
    end
    
    subgraph worktrees[独立 Worktree]
        WA[worktree-a: 日报周报合并]
        WB[worktree-b: 采购外包费用合并]
        WC[worktree-c: 四台账合并]
        WD[worktree-d: 未签台账合并]
        WE[worktree-e: 变更类型简化]
        WF[worktree-f: 财务配置合并]
    end
    
    M0 --> WA
    M0 --> WB
    M1 --> WC
    M1 --> WD
    M2 --> WE
    M2 --> WF
    
    WA -->|cherry-pick| M1
    WB -->|cherry-pick| M1
    WC -->|cherry-pick| M2
    WD -->|cherry-pick| M2
    WE -->|cherry-pick| M3
    WF -->|cherry-pick| M3
```

**规则**:
1. 每个开发者从 `main` 的当前基点创建独立 worktree 和分支
2. 开发者只提交自己 owned_paths 内的文件
3. 协调者先在 main 上提交共享文件改动，发布统一同步点
4. 开发者 rebase 到同步点后继续开发
5. 合入时协调者 cherry-pick 开发者的独占提交到 main
6. 每批合入后运行全量工程检查

## 8. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 共享文件冲突 | 中 | 高 | 协调者独占共享文件，开发者不碰 |
| 旧路由引用遗漏 | 中 | 中 | 合入后全局搜索旧路由路径 |

| 验收页面回归 | 低 | 中 | 合入后运行 `pnpm test:domain` |
| Worktree 磁盘空间 | 低 | 低 | 每批最多 2 个 worktree，用完即删 |
