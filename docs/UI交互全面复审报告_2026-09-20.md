> 方法：4 个只读审查 agent 并行（角色×导航×权限 / 端到端业务链路 / 页面内交互与冗余 / 历史文档对照），全部以 `src/` 代码为唯一事实来源，每条发现带 `文件:行号` 证据；🔴 级结论已由协调者逐条源码复核。

## 一、总体结论

- **主链路健康**：商机→评估→概算→提前投入→立项→项目→计划/预算→基线→执行→变更→验收→回款→结算→关闭→运维→归档 全线贯通；72 页写操作全部经 `useBusinessStore.dispatch → transition` 单一事实源，未发现绕过 store 的页面；未发现"放行"型越权；死链扫描干净。
- **但存在 3 个 🔴 阻断**，全部集中在"财务/领导视角"：财务登录即 403；集团领导与财务点击审批待办即 403（核心审批流对最终审批人断裂）；财务"成本确认"在状态机和权限矩阵中存在却无任何 UI 入口，结算退回闭环在 UI 层断裂。
- **系统性主题**：权限矩阵 / 状态机与 UI 存在多处"有权限无功能、有功能无入口、双轨并存"的不同步（🔴×1 + 🟡×8 同属此模式）。
- **历史文档**：5 份文档 26 条问题 → 19 已修复、3 仍存在、4 文档定性有误。文档整体滞后于代码，其中 4 条把刻意防御守卫误判为"死代码"。

## 二、🔴 阻断级（3 条，建议立即修）

### R1 财务专员登录即 403
- 证据：`src/routes/navigation.ts:6` `finance: '/executive/dashboard'`；`src/mock/configuration-access.ts:32` finance 页集 GL 仅 `[2]`（无 GL-01）；`MainLayout.tsx:106→323` 判否后渲染 403。
- 影响：财务首页直接 403，侧边栏也无 GL-01 入口。
- 建议：ROLE_HOME 改为 GL-02（`/executive/four-calculations`，若修复 R3 后可达）或 `/projects`（HS-01 财务有权）；或将 GL-01 加入 finance 页集。

### R2 `/approvals/:id` 鉴权错误 → 集团领导/财务点审批待办即 403
- 证据：`src/components/layout/MainLayout.tsx:96-101`，`/^\/approvals\/[^/]+$/` 写在 `PAGE_MANIFEST.find` 谓词内，对每个 manifest 页都命中 → `find` 恒返回第一个页面 WK-01；`:106` 鉴权退化为 `canAccessPage(用户,'WK-01')`。executive/finance 页集均为 `ids('WK',[2])`，无 WK-01 → `:323` 403。
- 影响：`src/mock/todos.ts:15` 生成的审批待办（重大成本变更/预算审批）`route: /approvals/${a.id}`，集团领导与财务点击即 403；而 `BudgetApprovalPage.tsx:21` 页内白名单本允许其进入。审批流对最终审批人断裂（pmo 因页集含 WK-01 侥幸可用）。
- 建议：approvals 特判移出 find（匹配时 currentPage 置 undefined，交给页内白名单），或为 approvals 维护独立 permissionPageId。

### R3 `confirm-cost` 有状态机、有权限、无 UI 入口
- 证据：`src/mock/business-domain.ts:163/:396` transition 存在（finance 专用，含重复/冻结校验）；`configuration-access.ts:23` finance 已授权；`src/pages/**` 全域 `confirm-cost` 触发点 0 命中（已复核）。实际成本入账由 `cost-orders.ts:76-78`、`labor.ts` 内部直写完成；`models/__tests__/settlement.test.ts:22` 结算金额退回后靠 `confirm-cost` 补录——该步无 UI 支撑。
- 影响：财务"直录成本/结算退回后重新归集"无页面出口，结算退回闭环在 UI 层断裂；权限页展示 `confirm-cost` 形成"有权限无功能"假象。
- 建议：在动态核算页或结算详情页补财务确认入口；或从状态机与权限矩阵移除，统一走单据入账。
