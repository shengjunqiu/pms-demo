## 一、已知未修复问题（流程图标注）

### 1.1 未签项目超限缺乏自动熔断 🔴

| 维度 | 说明 |
|------|------|
| **问题** | `UnsignedProjectControl.autoBlocked` 字段已添加，但业务逻辑从未检查该字段 |
| **代码位置** | `src/mock/cost-orders.ts`、`src/mock/business-domain.ts` |
| **现状** | 成本订单创建时未检查未签项目是否超限，超限后仍可继续发生成本 |
| **修复方向** | 在 `applyCostOrderAction` 和 `transition` 中检查 `autoBlocked`，超限时阻止新的成本订单 |
| **流程图** | 流程图-立项评审.md ⚠️ 标注 |

### 1.2 验收整改→重新验收路径不清晰 🟡

| 维度 | 说明 |
|------|------|
| **问题** | 验收不通过进入"整改中"后，用户需要先回复整改项再重新提交，但 UI 引导不清晰 |
| **代码位置** | `src/pages/settlement/AcceptancePage.tsx` |
| **现状** | `reply-acceptance` 和 `submit-acceptance` 逻辑完整，但页面缺少"回复整改→重新提交"的连贯操作指引 |
| **修复方向** | 在整改状态下添加步骤指引或向导组件 |

### 1.3 验收→回款联动不完整 🟡

| 维度 | 说明 |
|------|------|
| **问题** | `confirm-acceptance` 已实现回款计划标记（添加"【待收款】"），但仅对首次验收生效，且通过修改 title 字符串实现，非正式状态字段 |
| **代码位置** | `src/mock/acceptance.ts:92-96` |
| **现状** | 回款计划缺少 `status` 字段（如 `'待收款'\|'已收款'`），当前用 title 字符串 hack |
| **修复方向** | `ReceiptPlan` 添加 `collectionStatus` 字段，验收通过后正式更新该字段 |

### 1.4 成本变更缺少财务会签独立步骤 🔴

| 维度 | 说明 |
|------|------|
| **问题** | `ChangeRequest` 有 `assessments`（技术/财务/市场评估），但无独立的"财务会签"审批步骤 |
| **代码位置** | `src/mock/changes.ts`、`src/models/changes.ts` |
| **现状** | 评估完成后直接进入"待分级→待审批"，`requiredRole` 只能是 `pmo` 或 `executive`，无法表达"财务会签→PMO审批"串行链 |
| **修复方向** | `ChangeRequest` 添加 `financeSignoff` 字段，成本/资源变更必须财务会签后才能进入 PMO 审批 |
| **流程图** | 流程图-变更管理.md 已标注财务会签节点但代码未实现 |

### 1.5 结算→运维衔接机制不明确 🟡

| 维度 | 说明 |
|------|------|
| **问题** | 结算锁定后项目进入 `phase='收尾'`、`subPhase='项目结算'`，但运维类项目不会自动转入 `phase='运维'` |
| **代码位置** | `src/mock/settlement.ts`（lock 操作）、`src/pages/settlement/ProjectClosePage.tsx` |
| **现状** | `ProjectClosePage` 有导航按钮但无自动阶段切换逻辑；`isMaintenance` 字段存在但结算后未使用 |
| **修复方向** | 结算锁定后，对 `isMaintenance` 项目自动创建运维阶段记录并切换 phase |

## 二、新增发现的问题

### 2.1 Project.subPhase 缺少收尾子阶段值 🟡

| 维度 | 说明 |
|------|------|
| **问题** | `subPhase` 类型缺少 `'运维交接'`、`'后评价'`、`'归档'` 三个值 |
| **代码位置** | `src/models/types.ts:96` |
| **现状** | 结算后 `subPhase='项目结算'`，但后续的运维交接、后评价、归档无对应阶段值 |
| **影响** | 无法在阶段层面跟踪收尾期的详细进展 |
| **修复方向** | `subPhase` 添加这三个值，并在结算锁定后按项目类型流转 |

### 2.2 SettlementRequest 缺少各步骤时间戳 🟡

| 维度 | 说明 |
|------|------|
| **问题** | 结算流程 4 步（财务核算→PMO审核→结算评审→锁定）的 `history[]` 只记录操作人/动作，缺少每个步骤的独立时间戳字段 |
| **代码位置** | `src/models/settlement.ts`、`src/mock/settlement.ts` |
| **现状** | 无法精确计算每个步骤的耗时 |
| **修复方向** | `SettlementRequest` 添加 `financeConfirmedAt`、`pmoAuditedAt`、`reviewPassedAt`、`lockedAt` 等时间戳 |

### 2.3 日报工时输入缺失 🟡

| 维度 | 说明 |
|------|------|
| **问题** | `DailyReport.spentHours` 已被移除（始终为 0），但日报填报 UI 没有替代的工时输入控件 |
| **代码位置** | `src/pages/execution/ReportsPage.tsx` |
| **现状** | 日报可以填报完成内容，但无法记录实际投入工时 |
| **影响** | 工时管理（`Timesheet`）与日报脱钩，无法按日报维度统计工时 |
| **修复方向** | 在日报填报 Modal 中添加 `actualHours` 输入框 |

### 2.4 合同台账 Contract vs ContractLedger 数据分裂 🟡

| 维度 | 说明 |
|------|------|
| **问题** | `Contract` 接口 10 个字段，`ContractLedgerBasic` 接口 20+ 字段，两套数据可能不同步 |
| **代码位置** | `src/models/types.ts`（Contract 约 130 行，ContractLedgerBasic 约 260 行） |
| **现状** | 回款页面使用 `Contract`，合同台账页面使用 `ContractLedger`，更新一方不会同步到另一方 |
| **修复方向** | 统一为单一数据源，或建立同步机制 |

### 2.5 ReceiptPlan 缺少收款状态字段 🟡

| 维度 | 说明 |
|------|------|
| **问题** | `ReceiptPlan` 有 `paidAmount` 但无 `collectionStatus` 字段，验收→回款联动通过修改 title 字符串 hack 实现 |
| **代码位置** | `src/models/types.ts`（ReceiptPlan 接口）、`src/mock/acceptance.ts:92-96` |
| **现状** | 无法正式标记"待收款/已逾期/已核销"等状态 |
| **修复方向** | `ReceiptPlan` 添加 `collectionStatus: '待收款'\|'已逾期'\|'已核销'` 字段 |

### 2.6 四算科目树流程图未更新 🟢

| 维度 | 说明 |
|------|------|
| **问题** | 流程图-四算联动.md 的科目树只显示 SUB-04-1 到 SUB-04-4，但测试和代码中已有 SUB-04-5（交付培训费） |
| **代码位置** | `docs/流程图-四算联动.md` |
| **修复方向** | 更新科目树，添加 SUB-04-5 |
