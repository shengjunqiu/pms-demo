## 四、发现的潜在问题

### 🟡 4.1 `selectFourCalculations` — `income` 可能为 `undefined`（理论风险）

```ts
const income = project.revenueAmount ?? project.contractAmount;
```

如果 `revenueAmount` 和 `contractAmount` 同时为 `undefined`，则 `income` 为 `undefined`，导致：
- `sumMoney([undefined, -rolling])` → `NaN`
- `percentage(grossMargin, undefined)` → `NaN`

**当前 mock 数据中所有项目均有 `revenueAmount` 或 `contractAmount`，不触发。** 建议在 `selectFourCalculations` 入口处加默认值保护。

### 🟡 4.2 `settlementSnapshot` — 未签项目收入为 0

```ts
const ids = new Set(projects.filter((p) => !p.isUnsigned).map((p) => p.id));
```

`selectReceipts` 过滤掉未签项目，导致结算快照中 `income` 为 0。但未签项目无法通过结算条件检查（`committedCost`/`forecastRemainingCost` 不为 0），所以不影响实际结算流程，仅展示上收入为 0。

### ✅ 4.3 已确认无问题

- 所有 `sumMoney` 调用均使用 `money()` 精度控制，无浮点误差累积
- 所有 `percentage` 调用均有分母为 0 的保护（返回 `null` → 展示 `—`）
- 所有科目分摊使用 `allocateMoney` 末项补余差，总额精确
- 所有页面金额展示使用 `MoneyText` 组件，格式统一
- 所有数据源引用正确（使用 selector 而非直接读 mock）
