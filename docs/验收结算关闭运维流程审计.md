| 步骤 | 角色 | 状态 | 说明 |
|------|------|:----:|------|

**锁定步骤详细检查：**

| 检查项 | 状态 | 说明 |
|--------|:----:|------|
| 条件重检 | ✅ | 排除"无重复正式结算"外的全部条件 |
| 快照一致性 | ✅ | 成本列表、收入、预算ID、概算ID 须一致 |
| 重复锁定防护 | ✅ | `lockedProjects` + `已锁定已生效` 双重检查 |
| 阶段转换 | ✅ | `isMaintenance`→运维，否则→收尾/运维交接 |
| 结算记录创建 | ✅ | 含最终毛利和毛利率 |

**⚠️ 发现的问题：**

| # | 问题 | 严重度 | 说明 |
|---|------|:------:|------|
| 1 | **快照一致性检查不完整** | 🟡 | 只比较了 `costs`、`income`、`budgetId`、`estimateId`，未检查 `committedCost`、`forecastRemainingCost` 是否变化。如果 PMO 审核期间有成本处置操作改变了承诺/预测，锁定不会发现 |
| 2 | **`finance-confirm` 条件表达式** | 🟢 | `action.invoicedAmount!<0` 中 `!` 是 TS 非空断言，逻辑正确但写法易误解 |

## 七、跨流程联动检查

### 7.1 验收→回款联动

```
客户验收确认 (confirm-acceptance)
  → receiptPlans[].collectionStatus = '待收款'
  → 财务确认收款 (confirm-project-receipt)
  → contract.paidAmount 增加
```

**状态：✅ 完整**

### 7.2 结算→阶段转换

```
结算锁定 (review-settlement lock)
  → isMaintenance ? phase='运维' : phase='收尾', subPhase='运维交接'
  → 运维交接 (save-operation-handover + accept-operation-handover)
  → phase='运维', subPhase='质保运维'
  → 项目关闭 (confirm-project-close)
  → phase='已关闭'
```

**状态：✅ 完整**

### 7.3 未签→已签→启动

```
未签跟踪 (follow-unsigned)
  → 确认签约 (confirm-project-contract)
  → isUnsigned=false, contractAmount 设置
  → 确认启动 (confirm-project-start)
  → phase='执行', subPhase='开发实施'
```

**状态：✅ 完整**

### 7.4 结算→后评价→归档→关闭

```
结算锁定
  → 后评价 (start→save→score→confirm)
  → 归档文件 (submit→review)
  → 确认归档 (confirm-project-archive)
  → 运维交接/退出
  → 项目关闭 (confirm-project-close)
```

**状态：✅ 完整**
