## 三、发现的问题

### 3.1 未签自动熔断未实现 🔴

| 维度 | 说明 |
|------|------|
| **流程** | 成本订单/工时提交 |
| **问题** | `UnsignedProjectControl.autoBlocked` 字段已存在，但 `assertNewProjectCommitment()` 和成本订单/工时提交逻辑均未检查该字段 |
| **影响** | 未签项目超限后成本仍可继续发生 |
| **文件** | `src/mock/cost-orders.ts`, `src/mock/labor.ts`, `src/mock/business-domain.ts` |

### 3.2 结算→运维自动切换未实现 🟡

| 维度 | 说明 |
|------|------|
| **流程** | 结算锁定→运维 |
| **问题** | 结算锁定后 `isMaintenance` 项目不会自动切换 `phase='运维'`，需手动调用 `update-project-phase` action |
| **影响** | 运维类项目结算后仍停留在 `phase='收尾'` |
| **文件** | `src/mock/settlement.ts`（lock 分支） |

### 3.3 forecastRemainingCost 无日常更新入口 🟡

| 维度 | 说明 |
|------|------|
| **流程** | 成本预测 |
| **问题** | `forecastRemainingCost` 仅在结算时可处置（`dispose-settlement-balance`），日常执行中无更新入口 |
| **影响** | 滚动成本（rollingCost = actualCost + committedCost + forecastRemainingCost）中的预测部分无法日常更新 |
| **文件** | `src/mock/business-domain.ts` |

### 3.4 Project.rollingCost 与 selector 计算可能不同步 🟢

| 维度 | 说明 |
|------|------|
| **流程** | 成本计算 |
| **问题** | `Project.rollingCost` 是独立字段，`selectFourCalculations()` 通过 `actualCost + committedCost + forecastRemainingCost` 实时计算。如果某处更新了子字段但未同步更新 `rollingCost`，两者会不一致 |
| **影响** | 极小，`recalc()` 函数在关键路径上被调用 |
| **文件** | `src/mock/business-domain.ts`, `src/mock/selectors.ts` |

## 四、已确认正确的数据流

### 4.1 成本归集
- ✅ 成本订单：提交→财务批准（承诺+）→履约→验收→入账（承诺-，实际+）
- ✅ 工时：提交→PM审核→实际成本+（承诺成本-）
- ✅ 滚动成本 = actualCost + committedCost + forecastRemainingCost
- ✅ 成本偏差 = rollingCost - budgetAmount

### 4.2 四算联动
- ✅ 概算→预算超概算检查（总金额 + 科目 10% 阈值）
- ✅ 预算→核算实时对比（超支预警）
- ✅ 结算快照一致性检查（锁定前对比成本/收入/版本）

### 4.3 变更管理
- ✅ 变更申请→影响评估→分级→审批→新基线
- ✅ `confirmBudgetBaseline()` 正确更新基线、预算、WBS、里程碑
- ✅ 变更通过后项目进度、工期、收入同步更新

### 4.4 验收流程
- ✅ 内部初验→供应商验收→客户终验 三阶段完整
- ✅ 8 项前置条件检查（范围基线、WBS、需求/BUG、问题、质量、材料等）
- ✅ 整改→回复→重新提交闭环

### 4.5 结算流程

- ✅ 锁定前快照一致性检查
