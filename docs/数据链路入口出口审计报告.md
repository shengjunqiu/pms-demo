## 三、轻微缺陷（2 个）

### 3.1 `ticketMeta` — 有入口无页面直接消费 🟡

| 维度 | 说明 |
|------|------|
| **入口** | `create-ticket` / `update-ticket` 在 `tickets.ts:55` 创建 |
| **出口** | 仅在 mock 逻辑中被读取（`configuration-finance.ts` 的预警规则、`closeout.ts` 的归档快照），**无页面直接展示** |
| **影响** | 事项的扩展元数据（描述、分类、截止日期等）仅在 TicketsPage 的基础字段中展示，`ticketMeta` 中的额外信息不可见 |
| **建议** | 在 TicketsPage 的详情 Drawer 中展示 `ticketMeta` 内容 |

### 3.2 `qualityPlans` — 有入口无页面直接消费 🟡

| 维度 | 说明 |
|------|------|
| **入口** | `quality-plan` action 在 `deliverables.ts` 创建 |
| **出口** | 仅在 `DeliverablesPage` 中通过 `qualityPlan()` selector 间接读取，**无页面直接展示 `qualityPlans` 原始数据** |
| **影响** | 质量计划数据只能通过 selector 的派生数据查看，无法直接浏览/编辑原始质量计划记录 |
| **建议** | 影响极小，selector 已覆盖消费需求 |

## 四、死链路（1 个）

### 4.1 `maintenanceCosts` — 永远无法写入 🔴

| 维度 | 说明 |
|------|------|
| **定义** | `BusinessState.maintenanceCosts: CostItem[]` |
| **入口** | `confirm-cost` action 中 `if (action.maintenance) { throw new Error('运维费用请通过周期原单填报和财务审核入口，不允许直接入账'); }` |
| **出口** | 无页面读取 |
| **问题** | 该字段有定义，但唯一写入路径直接抛异常，**永远无法写入任何数据** |
| **影响** | 运维成本无法通过 `maintenanceCosts` 记录，实际运维成本走 `operationCycles` + `operationCostSources` 路径 |
| **建议** | 移除 `maintenanceCosts` 字段（死代码），或实现真正的运维成本入账逻辑 |
