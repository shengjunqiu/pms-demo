## 1. 已修复

### A2 内部初验被工单门禁永久锁死（真实阻断）

- 现象：种子数据的需求/工单发起人写的是业务方名称（如 `客户业务处`），不是内部账号；而 `update-ticket` 的 `confirm`/`return` 要求 `creator === actor.name`。没有任何可登录用户能匹配该名称 → 高优需求永远停在 `待验证`，内验准入条件「关键需求与BUG」永久阻断 → 项目无法收尾。
- 领域修复 `src/mock/tickets.ts`：识别“发起人不是内部账号”（`externalCreator`），允许 **项目主 PM 或 PMO 代理确认**，并在处理历史写入 `[代理确认·原发起人 X]`，保留原发起人与代理原因。其他角色仍被拒绝。
- 待办修复 `src/mock/todos.ts`：确认责任人回落到项目主 PM，PM 待办里能看到这些“最终确认”事项。
- UI 修复 `src/pages/tickets/TicketDetailPage.tsx`：按钮可用性判定与领域规则对齐（此前只认 `creator`，PM 按钮恒为禁用，领域放行也无从操作），当前任务与规则文案补充代理说明。
- 新的冗余消除 `src/pages/workbench/TodosPage.tsx` + `src/models/todos.ts`：待办新增「办理身份」列（审批 / 主PM / 责任人 / 最终确认 / 督办 / 审核），直接回答“这条待办是以什么身份给到我的”。
- 回归：`src/models/__tests__/tickets.test.ts` 新增 2 个用例（代理确认 + 历史留痕、PM 待办含最终确认项且标注身份）；`e2e/smoke.spec.ts` 断言待办列与详情页按钮对 PM 可用。

## 2. 已修复（第二阶段）

### 构建守卫用未压缩体积比 gzip 预算（误报超预算）

- 现象：`pnpm build` 报“首屏 JS 1294.1 KB 超出预算 700 KB”，但脚本注释写的是“预算（gzip 字节）”，实际用的是 `statSync().size`（未压缩）。真实 gzip 首屏为 **410.0 KB**，本来在预算内。
- 修复 `scripts/check-chunks.mjs`：改为 `gzipSync` 计量，明细同时列出 gzip / raw，输出“gzip 410.0 KB / 未压缩 1294.1 KB”。现输出 `✓ 首屏 JS gzip 410.0 KB 在预算 700.0 KB 内`。

### 归档页 e2e 覆盖（此前只有 domain 覆盖）

### 归档页禁用按钮的就近原因（JS-10）

### 运维详情页按钮置灰无解释（JS-12）

- 背景：复核“项目经理打开 `/operations/OPS-007` 得 403”时确认——该周期属于 P-007（PM 郑经理 U-008，`teamIds=[U-008]`），当前“项目经理”角色固定为张建国 U-001，既非该 PM 也不在周期团队。页面守卫 `visibleProjects(...) || c.teamIds.includes(currentUser.id)` 判定为拒绝，**属设计如此，不是权限配置缺陷**。
- 顺带发现真问题：财务/admin 依靠 `dataScope='all'` 能进入页面，但「登记运维记录」「填报运维工时/费用」「配置到期提醒」「办理续期」「办理退出」均置灰且无任何原因；而 PMO 按 `canAccessAction`（`actor.role==='pmo' || cycle.teamIds.includes(actor.id)`）确实可办。
- 修复：`src/pages/settlement/OperationsPage.tsx` 新增 `blockReason(kind)` + `gate(kind, button)`，五个动作按钮置灰时用 Tooltip 就近说明是“由本周期运维团队或 PMO 办理”、“由本项目项目经理或 PMO 办理”、“待生效周期需先检查并激活”还是“权限策略未开放”。
- e2e：新增 `e2e/operations.spec.ts`（3 例）——PM 得数据范围 403、PMO 可真实办理、财务置灰且 Tooltip 文案正确。

### 指标卡单位/精度错位（一整类 UI 缺陷，截图发现）

- 现象：`MetricStatCard` 的 `unit` 默认值是 `'万元'`，非金额卡片没传 `unit` 时就会渲染成“归档准备中 **万元**”“未结算 万元”“移交给谁 … 万元”；同时数值一律 `toFixed(2)`，计数类变成“0.00 个 / 0.00 份”。
- 修复：为 13 处非金额卡片显式传 `unit=""`（归档状态、前置结算、移交状态、接收责任人、前置档案、周期状态、后评价状态、模板加权分、关闭状态、应收结清、结算状态、建设毛利率、毛利率）；` MetricStatCard` 改为按单位决定精度（金额 2 位，计数整数 0 位，其余保留原 2 位）。
- 实测：“归档状态 | 归档准备中”“前置结算 | 未结算”“运维周期 | 0 | 个”“正式文件 | 0 | 份”，金额卡仍为 `5,538.30 万元`。
