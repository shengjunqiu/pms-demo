## 二、P0 阻断

### QA-01 新立项申请页只读，提交死锁

- 角色：客户经理（陈亮）
- 路径：`/opportunities/OPP-068` → 「发起立项」→ `/initiation/apply?opportunityId=OPP-068`
- 复现：
  1. 商机详情点「发起立项」（按钮可用，前置校验已通过）
  2. 进入 `/initiation/apply?opportunityId=OPP-068`
  3. 页面只有 `Descriptions` 只读展示，**0 个 `.ant-form-item`**，无法填写名称/必要性/建议/区域/范围/客户需求/计划日期/附件
  4. 点「提交立项申请」，被拦截：`请补全「立项申请详情」页签的必填申请资料后提交`；保存草稿同样无法补齐
- 期望：能补录立项申请资料并提交，进入 PMO 风险评估
- 根因：`src/pages/initiation/InitiationApplyPage.tsx`
  - `save()`（约 121-131 行）从 `form.getFieldsValue(true)` 取 `name/necessity/recommendation/region/scope/customerNeeds/plannedStartDate/plannedEndDate/expectedSignDate/files` 做必填校验
  - 但表单区（约 201-390 行）没有任何 `Form.Item`，全部是 `mockDetailData` 拼出的 `Descriptions`；`Form` 初始值有数据，表单控件却不存在
  - 附件也没有真正上传控件，只展示文件名
- 影响：**新商机无法从 UI 起跑立项**；种子里的 INIT-1/2/3 掩盖了这个问题。任何新演示商机都会卡死在这里
- 建议：按校验字段补 `Form.Item`（或从商机/方案自动带入只读 + 允许补录差异），并把附件接 `Upload`；提交前校验与页面字段保持同一份 schema

## 三、P1 高优先级

### QA-02 审批详情页切角色必被踢回角色首页，原单上下文丢失

- 角色：财务 → PMO（APR-1 三角色会签）
- 路径：`/approvals/APR-1`，财务复核通过到节点 2/3 后，顶部切「PMO负责人」
- 实际：直接跳到 `/executive/dashboard`，不在原单；必须自己再进「待办中心」→ APR-1。P0 阻断感来自“找不到刚才那张单”
- 根因：`src/components/layout/MainLayout.tsx:75-98`
  - `const currentPage = isApprovalsDetail ? undefined : PAGE_MANIFEST.find(...)`
  - `canStay = !!currentPage && canAccessPage(...)` → 审批详情恒为 false → `navigate(ROLE_HOME[val])`
- 反证：同一页面内切身份（不刷新、不跳首页）时，APR-1 链路完全正常：
  - 财务 1/3 → PMO 2/3 → 集团领导 3/3 → 通过 → PMO「确认基线生效」
  - 生成 `V2.0`，预算 `3,340.48` 万元，基线已生效（数据层与 UI 双重确认）
- 建议：审批详情属于可停留页；切换后若新角色是当前节点审批人，保留 `/approvals/:id`，否则显示 403 并给“返回待办”按钮，而不是静默跳首页

### QA-03 结算核算事项不进财务待办，也没有跨项目结算入口

- 角色：财务（刘敏）
- 证据：
  - 财务待办 21 项中无任何 `SREQ-`（全量数据里财务待办 52 项，也没有 SREQ）
  - `/workbench/todos` 代码无结算事项聚合（`src/mock/todos.ts` 无 SREQ/settlement 分支）
  - `/settlement` 全局列表 404（只有 `/projects/P-023/settlement` 单项目路由）
  - P-023 的 SREQ-2 确实停在「财务核算」，且「财务核算确认」弹窗可用，可录开票额/税额/意见
- 影响：财务能办理，但必须先知道 P-023 这个项目号，从项目台账点进去；没有“我的结算核算队列”，跨项目结算不可发现
- 建议：
  1. 待办增加 `settlementRequests.status==='财务核算'`（以及 PMO 材料审核、结算评审）聚合
  2. 补跨项目结算工作台或在导航“验收结算”下加结算列表；若暂不做，至少让待办可直达

### QA-04 立项入口与决策权限状态机不一致

- 角色：客户经理 / PMO
- 证据：
  - OPP-068 已是「拟立项」，系统里已有 INIT-2，但详情页「发起立项」仍可用（`OpportunityActions.tsx:22,29` 只校验 `initiationPrerequisites`，不校验是否已有立项/是否已转立项）→ 可重复进入申请页，叠加 QA-01 后变成重复建单 + 死锁
  - PMO 的 INIT-1 在风险评估后，「立项决策」按钮禁用且无明确“该谁发起”的提示；但待办里 INIT-2/INIT-3 又直接给 PMO `/initiation/INIT-2/decision`
  - 客户经理待办为 0，但 OPP-068/OPP-069 仍在推进中
- 影响：同一个 PMO 在不同轮次权限不同；市场看不到自己该做什么；容易重复建单
- 建议：统一“谁发起决策、谁决策”的规则；入口按商机状态和已有立项单隐藏/禁用并给出原因；待办按“当前办理人”聚合

## 四、P2 中优先级

### QA-05 配置深链不落对应 Tab

- `/settings/cost-mapping`、`/settings/cost-baseline`、`/settings/alerts` 都激活“四算科目与映射”，不落到成本基准/预警规则 Tab
- 三条路由复用同一页面（`src/routes/modules/configuration-finance.tsx:5` 附近），未见 path→tab 绑定
- 影响：书签/待办深链指错位置；用户以为页面没保存成功
- 建议：从 `useLocation().pathname` 派生 `activeKey`

### QA-06 P-008 已结算/已关闭，但归档与后评价仍未完成

- P-008 状态「已结算 / 已关闭」，但：
  - 归档 6/14 类、正式文件 0 份、归档准备中，「确认正式归档」禁用（缺件禁用本身合理）
  - 后评价「未发起」
- 影响：关闭状态与子状态矛盾；如果按“已关闭”过滤，会漏掉仍需补档/后评价的项目
- 建议：要么关闭前强制归档/后评价完成，要么把状态改为收尾/待归档；至少加一致性校验

### QA-07 变更草稿保存提示文案错误

- `/projects/P-001/changes/new` 填标题/原因后「保存草稿」，toast 为「原变更事项状态已更新」
- 期望：「草稿已保存」；当前文案会让人误以为动到了原变更/基线

### QA-08 待办中心噪音大，审批事项不突出

- PM 待办 90 项（含需求/BUG/任务/风险），PMO 37、财务 52；「待办中心」与「执行任务」混在一起
- 虽有业务类型筛选，但默认列表没有“待我审批/待我办理”优先分组，跨角色演示时很难快速找到审批单
- 建议：默认按“待我决策/待我办理/我跟进”分组或加默认筛选；任务类留在工作台

## 五、P3 低优先级 / 文案与一致性

- 商机原始名带下划线编号：`2026年数字化转型商机_68`、`_66`，在待办/评审标题中直接展示；建议展示清洗后的商机名
- `/settlement`、`/projects/P-001/contract` 等不存在深链统一 404；如果这些是文档承诺页面，需要补路由，否则从前端导航/文档移除
- 已签项目合同台账只读、无“用印/合同版本”；合同签订动作只在未签立项台账（P-004）里。若四算范围包含已签合同管理，这是缺口；若只做未签转已签，则属于范围说明缺失
- 启动确认页点「确认正式启动」后仍停留在检查页，只给 toast；没有跳转到“执行中”或刷新按钮状态，容易被误认为没生效（d1 观察，建议复核）
