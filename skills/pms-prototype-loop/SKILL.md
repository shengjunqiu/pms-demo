# 项目四算原型 Loop

把“概算 → 预算 → 核算 → 结算”与“全局经营 → 异常 → 项目 → 原始业务 → 决策”实现为可连续演示的前端原型。完成的单位是有证据的业务页面，不是文件或已注册路由。

## 启动与适用范围

1. 确认当前目录或用户指定目录是项目根目录；检查适用的 `AGENTS.md`、现有代码、锁文件和用户未完成的修改。不要假设存在 Git。
2. `references/catalog.json` 的 `sources` 列出四份原文路径。首次开发通读四份文档；恢复时先核对指纹，再读当前任务涉及的章节。查字段、规则、页面优先使用原文。
3. 先读 [业务模型与已知差异](references/domain.md)，再读 [Loop 协议](references/loop-protocol.md)。涉及 Mock、经营计算或数据状态时读 [数据契约](references/data-contract.md)；实现及验收页面时读 [验收说明](references/acceptance.md)。
4. 将下例的 `SKILL_DIR` 设置为本次加载的技能实际目录，不把个人主目录写进应用代码。

```bash
SKILL_DIR="/absolute/path/to/pms-prototype-loop"
python3 "$SKILL_DIR/scripts/loop.py" --root "$PWD" inspect
python3 "$SKILL_DIR/scripts/loop.py" --root "$PWD" init
python3 "$SKILL_DIR/scripts/loop.py" --root "$PWD" status
python3 "$SKILL_DIR/scripts/loop.py" --root "$PWD" next
```

`inspect` 为只读文档校验。`init` 幂等建立 `.pms-loop/state.json`，维护 `DEV_PROGRESS.md` 的专属区块，保留既有手写内容。创建/修改这个技能本身时，只在临时项目测试这些命令，不据此启动 72 页应用开发。

## 范围与优先级

- 本阶段按任务书使用 React 18+、TypeScript、Vite、Ant Design 5.x、React Router 6+、dayjs、@ant-design/icons；空项目用 pnpm，已有锁文件保留包管理器。安装时核对版本与官方兼容说明，避免无约束安装将 Ant Design 升为其他主版本。
- 业务与页面描述差异按“页面清单 V1.1 → 详细功能清单 V1.1 → PRD V1.1”处理；任务书指定原型边界、栈、72 页范围、Mock数量、工程检查。推荐制作顺序的差异不构成阻塞。
- 前端模拟审批、权限、消息、文件名和数据变化；不引入真实服务端、数据库、外部消息、真实业务集成或生产部署。337 个功能点包含集成与生产非功能要求，不将其当成本原型真实上线承诺。
- 用户要求“持续开发/直到完成”时，在当前执行会话连续迭代；用户只要求指定页面、一轮、检查或技能修改时遵守该范围。原文“不能停止”不覆盖用户中止、环境权限或运行时限制。

## 每轮工作

1. **恢复事实**：读取 `DEV_PROGRESS.md`、结构化状态、活动轮次及源码。原文指纹改变时先阅读差异并维护目录映射，不仅更新哈希来绕过检查。
2. **选择闭环**：每轮 1–5 个相关页面或公共能力。`next` 给出建议，允许依赖驱动调整。先完成 FND-01 工程和设计系统、FND-02 统一 Mock；之后以任务书第 16 章为阶段顺序。领导下钻依赖的 HS-01、HS-13、HS-08 等可提前纳入同一批；入口跳到占位页不能通过验收。
3. **建立轮次**：运行 `begin --items ID ...`，检查生成的 `plan.json` 和 `evidence.json`。每页有来源、建议路由、功能映射和独有验收项。具体化字段、状态、规则和下钻目标；UI细节自行补齐并记录假设。
4. **完整实现**：路由/导航、统一数据、中文内容、核心动作、校验、空态/加载态、业务跳转、两种桌面宽度一起完成。采用公共组件；WBS、预算、审批、验收、分析仍须保留各自信息结构。
5. **验证修复**：执行 `check`，运行项目的 typecheck、lint、build；数据轮次及最终轮次要求 `test:domain`，最终轮次还要求 `test:e2e`。浏览器检查新增页面及受影响链路，截图1440×900、1280×900，查看截图与控制台。验证失败则修复同轮。
6. **提交证据**：将实际操作、预期与观察结果及本地证据路径写入本轮 `evidence.json`，逐项确认通用和专属条件，再运行 `accept`。未做的检查保持false；没有浏览器时保留待验收，不能把编译通过当作视觉通过。
7. **继续推进**：`accept` 自动更新计数和进度；继续 `next`。公共组件或计算变化影响已完成页面时回归；发现失效用 `reopen --items ... --reason ...` 退回。用 `note --text ...` 保存假设、依赖和准确下一步。

```bash
python3 "$SKILL_DIR/scripts/loop.py" --root "$PWD" begin --items GL-01 GL-05 HS-01 HS-13 HS-08
python3 "$SKILL_DIR/scripts/loop.py" --root "$PWD" check
# 按真实验证填写命令打印的 evidence.json，证据保存在项目内。
python3 "$SKILL_DIR/scripts/loop.py" --root "$PWD" accept
```

## 业务不可破坏的约束

- 项目、商机、合同、成本、决策项保持来源关联；前期成本继承到项目只计一次。
- 生命周期阶段、执行子阶段、审批/执行状态分别建模；四阶段分布用统一映射。
- 生效概算/预算/范围/WBS/里程碑/资源保留版本快照；审批绑定提交时版本；变更通过追加版本。
- 四算、项目摘要、数量、组织汇总从统一selector计算。已发生、未发生承诺、剩余预测互斥；比率处理零分母，组合毛利率用汇总金额计算。
- 健康度、分级、审批、额度集中配置并标注“演示规则”；显示命中原因及明细入口。
- 需求/BUG由发起人最终确认；问题由项目经理最终关闭；风险转问题保留原对象。
- 阶段门检查里程碑和审核通过的必交材料；结算检查验收、未决成本、重复结算，锁定建设期成本；运维成本按周期分开。
- 领导下钻使用同一角色/组织/时间等筛选上下文，返回保留筛选及滚动位置；待决策跳转原审批，工作台和驾驶舱不复制业务维护流程。

## 完成、恢复与阻塞

72页全部经 `accept` 后进入 `FINAL`；按任务书第19–21章做全量回归、两条角色演示与五条业务链路，补齐 README、路由说明、Mock说明。最终轮次全部证据通过，脚本才标记 `complete`。

每轮向用户说明完成页、验证结果、剩余事项。上下文压缩或会话结束前用 `note` 记录活动轮次、准确下一步、失败命令；恢复沿用同轮。脚本是任务与证据控制器，不在后台启动Codex，也不自行生成下一会话。

真实阻塞时尝试有意义的替代方案；仍不能推进用 `defer --reason ...` 保存当前轮次并转独立任务。权限/必需输入不可绕过。可做工作耗尽时如实汇报阻塞与恢复动作，不谎称完成，不无限重复失败命令。
