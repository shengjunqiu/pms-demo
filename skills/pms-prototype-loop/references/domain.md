# 业务模型与原文导航

## 产品理解

平台服务集团型、多组织项目制企业。主办/市场、方案、技术、交付、项目经理及成员负责业务与执行；财务确认成本口径；PMO负责阶段门和监督；PMC处理重大项目、风险与变更。客户是外部验收主体，原型不另建客户门户。

| 四算阶段 | 关键处理 | 留存输出 |
|---|---|---|
| 概算 | 初评→方案→技术成本→专家评审→概算；可申请提前投入 | 冻结概算、方案版本、意见、风险、前期成本 |
| 预算 | 立项分级/会签/PMO/PMC→任命→WBS/资源→预算→基线 | 正式项目、范围/进度/成本/资源基线、未签额度 |
| 核算 | 执行、工时和各类成本、风险问题、变更、阶段切换 | 实际与承诺成本、预测、过程记录、新基线 |
| 结算 | 内部/供应商/客户验收→财务/PMO评审→四算→后评价→归档 | 冻结结算、经营结果、关联运维周期或关闭 |

## 容易丢失的业务规则

| 场景 | 必须呈现的行为 |
|---|---|
| 商机转拟立项 | 初评条件满足后开启方案任务；暂缓有原因、复评日和责任人 |
| 商机终止且有投入 | 先记录成本处置说明/复盘；保留来源，不删除历史成本 |
| 专家评审整改 | 整改项、责任人、截止日明确；回复后新一轮评审，保留旧版本 |
| 提交立项 | 带入商机、方案、冻结概算、风险、意见、前期成本，显示来源版本 |
| 项目分级 | 日常且毛利达标走会签，日常异常走PMO，重大/高风险走PMC；显示命中规则 |
| 项目经理 | 唯一有效主PM；拒绝接收时重新任命；退出成员的历史责任不回写 |
| WBS | 树形任务与甘特；叶子任务有责任人/日期；依赖无环；生效后编辑引导变更 |
| 超概算 | 可保存草稿；提交要求原因并转高级审批，不笼统禁掉保存 |
| 审批期间上游变化 | 审批单引用提交时版本，不偷偷切换概算 |
| 未签投入 | 已立项不等于已签；额度、有效期、签约进展独立；超限追加投入需审批 |
| 正式启动 | 检查立项、任命/接收、有效基线、合同状态，不仅改状态标签 |
| 日报 | 模拟自动待办；无进展需原因；问题/风险为独立对象；周报从统一数据聚合 |
| 需求/BUG | 需求有行业线/产品字段；BUG有复现、预期/实际结果；转办同步责任人，最终由发起人确认 |
| 问题/风险 | 一般/重要/重大有语义；问题由PM最终关闭；升级不等于关闭；转问题保留风险 |
| 重大新增需求 | 影响范围、成本、关键进度时关联变更，不在需求单里直接实施后关闭 |
| 工时 | 有效成员、单日累计上限、重复/阶段/额度约束；审核有效才计成本；成员不见个人成本单价 |
| 变更 | 原基线→影响评估→分级决策→新基线；驳回保持旧版；新增范围成本按规则限制 |
| 阶段门 | 里程碑业务完成不等于可切阶段；材料必须齐全且审核通过；列明阻断项和补齐入口 |
| 验收 | 内部、供应商、客户各有条件/整改轮次；无供应商明确不适用；客户通过有证明和确认 |
| 报验 | JS-04有类型、金额、分税点和材料；分批累计受合同规则约束 |
| 结算 | 检查最终验收、未决成本、未重复结算；提交冻结建设期成本入口，财务确认后冻结结果 |
| 历史补录 | 不覆写结算；演示调整则新版本、差异、审批记录 |
| 运维 | 接收人确认交接；SLA/周期/服务范围完整；建设与运维成本分开；新增建设走新商机/周期 |
| 归档关闭 | 正式文件只读；关闭检查遗留事项、重大问题、材料、后评价和运维状态 |

## 文档差异的处理记录

以下差异可按明确口径处理，不构成暂停整个开发的理由：

1. 页面清单写“70+”，任务书明确72且逐项列出；精确计数为72。337是功能点，不是一功能一页面。
2. 页面文档先工作台骨架，任务书先领导视角；使用任务书调度建议，依赖页面可前置。
3. WK-01字段写“预算−已用/滚动”，动态核算/任务书用“滚动−预算”。统一“预测成本偏差”为滚动−预算，正数超支；“剩余预算”为预算−实际。如展示预算−滚动，另名“预计预算结余”。
4. “已发生+未发生预计”等价于“已发生+已承诺+剩余预测”的前提是后两项互斥；实现三桶并消除重复。
5. 实施/初验/试运行是执行子阶段；四算阶段用统一映射。关闭是状态，运维不新增第五种四算。
6. P-004的8,800万在任务书写作“合同额”但同时未签。原型用拟签/立项金额，不纳入已签合同额，并标明口径。
7. 项目台账可为额外导航入口（如`/projects`），不计第73个验收页。质量计划/检查嵌入HS-17、HS-01或JS-01；缺独立编号的原审批详情用关联Drawer/子路由。
8. IN-001~010和生产鉴权、租户隔离、定时消息仅模拟可见行为；更新时间和延迟为演示，不声称真实接入。
9. 阶段门示例“重大未关闭问题：需说明”不代表全部可放行；按演示规则区分阻断与可说明项，必交材料审核失败仍阻断。
10. 立项采用页面文档的通过/整改/否决/暂缓；专家评审保留通过/整改/不通过语义；状态和阶段独立。

新冲突若改变整体架构且无法按优先级消解，记录双方出处和影响再询问；一般字段、日期、UI细节记录假设后继续。
